## 已确认并修复

### U1 · P2 · 入口去重依赖输入数组顺序

- 文件：`backend/src/analytics/inviteRegistration.js`。
- 同一用户、会话、匿名身份和邀请码的多个入口观察，原来保留数组中先出现的一条，而非时间最早的一条。
- 反例：入口 2000ms，注册 3000ms，绑定 3500ms，登录 4000ms；另有 4500ms 的重复页面观察。将后者放在输入首位，结果从注册成功变为待登录。
- 影响：转化窗口、注册判断以及统计期归属会随输入顺序变化；统计期外的原始入口可能被期内重复观察替代。
- 修改：先按事件时间、事件 ID 稳定排序，再去重，最后应用统计期。复制数组后排序，避免修改上游输入。
- 验收：乱序与正序返回相同结果；期外首次入口不会被期内重复观察重新计入。

### U2 · P2 · 缺少访问标识时，仅凭账号关联登录

- 文件：`backend/src/analytics/inviteRegistration.js`。
- 原来 session_id、anonymous_id 均缺失时，会退回 actor_user_id 匹配。同一账号其他访问的登录因此也能被当成本次邀请入口的登录证据。
- 影响：访问证据不足仍可能确认新增邀请成功，与现有需求中的“使用会话及匿名身份关联入口后的真实登录”不符。
- 修改：保留会话匹配和匿名身份匹配；两者都缺失时不确认登录关联，记录保持 `login_pending`，不强行计成功。
- 验收：保留同一账号、合法注册和绑定时间，但移除全部访问标识，成功人数为 0。

### U3 · P2 · 缺少 properties 会使整项注册分析抛错

- 文件：`backend/src/analytics/inviteRegistration.js`。
- 入口已有 referral 比较键，但未携带 properties 时，读取 referral_link_id 会抛出 TypeError。
- 修改：缺失 properties 按空对象处理，链接和活动保留 unknown，不补造属性。
- 验收：缺属性入口正常返回可诊断记录。
- 边界：这是分析函数的容错缺陷；本轮没有证明真实数据读取器正在产生这种输入。

以上 4 条新增回归用例在修改前全部失败，修改后通过。

## 优化实施 · 用户确认执行后

### 1. 邀请注册事件索引（完成）

- 按会话、匿名身份、会话与匿名身份组合建立索引，入口直接读取对应事件数组，避免每个入口扫描该用户全部事件。
- 保留最早入口去重、跨身份冲突、时间窗、过滤前去重认领及无访问标识不确认登录等规则。
- 新增组合匹配回归：不同会话不能混入；仅匿名标识、仅会话标识可分别关联；同会话但匿名身份不同不得关联。
- 可复用基准：`backend/test/inviteRegistration.bench.cjs`。在仓库根目录运行 `node --expose-gc backend/test/inviteRegistration.bench.cjs`；可传旧版本模块绝对路径作输出一致性比较。
- 本机合成基准：1 个用户、3,000 个会话、30,000 条事件，基线 4,418.73ms，索引版 46.19ms，完整返回值深比较一致；序列化结果均为 37,793 字节。
- 堆内存增量约从 7.00MB 到 8.55MB，索引以额外内存换取速度。此结果是单次合成测试，不是生产延迟、峰值内存或百万用户性能承诺。

### 2. 内存结果缓存与重新计算（完成）

- `resultCache.js` 的分析结果最多 200 条，短期指标 memo 最多 100 条。写入先清理过期项，再按插入先后淘汰；覆盖 memo 时更新其插入顺序。
- 到达 TTL 边界即过期，读取不会延长快照寿命。
- 下钻名单被淘汰后，memo 同时视为未命中；重新运行指标会重新计算，避免反复返回已经失效的下钻 ID。
- 原下钻请求仍返回 409 和“分析结果已过期，请重新运行”；不自动替换用户已经固定的名单。
- 新增容量、覆盖顺序、TTL 边界、失效下钻引用的 4 条测试；已有留存路由过期测试继续通过。
- 采用条数上限，未声称实现按字节限制内存；生产结果大小仍需持续观测。Hologres 的持久作业缓存由原作业机制管理，此处只调整该内存缓存模块。

### 3. 前端按需加载与 JSON 隔离（完成）

- 图表初始化移动至 `chartRuntime.js`，登录和数据获取完成后才加载，登录页不再先加载完整 ECharts。
- 北极星、漏斗、邀请/登录转化、路径、留存、推荐、交易页按访问动态加载，原始/聚合版本按当前模式选择。
- 新增 `lazyPage.js`：加载状态、加载失败重试、切页后取消待激活模块，并继续转发页面销毁和未应用筛选状态。
- JSON 模式改为请求独立 JSON 资源；数据归一化抽至 `jsonDatasetCore.js`。原同步 `datasetFromJson()` 保留兼容，生产启动走异步加载器。
- 完整比较同步与异步结果相等；网络错误、资源 404 明确失败，不回退默认数据。
- 浏览器复核额外发现 JSON 模式请求后端运营标签导致解析错误；现在仅在后端数据模式挂载该入口，JSON 页面不发这类请求。
- Dashboard 构建文件约 574.17KB → 401.6KB；原约 5.70MB 的 JSON JavaScript 模块改为独立数据文件。数据内容保持不变，原始 JSON 事件资源约 7.38MB（含排版，gzip 约 277.57KB），不能将此次调整理解为数据总下载量下降。
- 图表库仍约 655.65KB，构建仍提示该 chunk 大于 500KB；本轮实现延后加载，没有通过调高阈值隐藏提示。

### 4. 邀请口径、人群时间与接续文档（完成）

- 邀请页默认展示“新增注册邀请校验”；历史证据关联及显式埋点流程放入可展开的辅助核对区，原功能和下钻保留。
- 有效起点优先读取后端 `effective_from`，旧响应保留原起点兜底；不再让前后端各自硬编码不同起点。
- 本地圈选、远程下钻及统一应用人群时补记名单固定时间；继续保留标签基础人群、筛选描述及已有数据截至时间，更新数据不重写名单固定时间。
