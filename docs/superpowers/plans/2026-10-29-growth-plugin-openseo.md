# Growth Agent 可插拔能力与 OpenSEO 实施计划

> **开发 Agent：**按阶段逐项实现、验证和提交。先阅读本文件、仓库适用的 AGENTS.md 和现有实现；每个阶段提供独立可审查的提交。不要把模拟测试描述为真实外部服务验证。

**目标：**让 Growth Agent 在保留内部业务数据与现有 GSC 能力的基础上，通过受控连接器使用自部署 OpenSEO，并为后续数据服务扩展提供稳定入口。

**架构：**现有工具经兼容层与新增能力进入统一目录；调用经过权限、任务范围、预算、输入输出和证据网关。连接器负责外部协议，技能负责组合能力；插件结果必须有来源清晰、owner 隔离的证据和有界模型投影。

**技术栈：**现有 Node.js CommonJS 后端、node:test、现有 SQLite 证据存储与 PostgreSQL AI 数据库；自部署 OpenSEO Streamable HTTP MCP。具体依赖版本、配置及迁移遵循项目现状与实际服务协议。

## 范围与约束

- 只加载随项目发布、经审查的连接器；不实现任意第三方代码安装、运行时下载、插件市场或自建 MCP 服务。
- 不强制把现有内部工具改写为 MCP，也不一次性迁移或重写既有业务工具。
- 现有工具 ID、权限、证据、scope、结果语义和 Growth 任务恢复行为须兼容；保持现有 GSC 第一方同步与快照。
- OpenSEO 自部署；服务端配置其地址、凭据与项目映射。模型和客户端不能指定任意地址、密钥或其他用户的项目；默认不启用，失败不得阻断内部工具。
- 只读不等于免费。首个 OpenSEO 能力只读已有排名快照，不触发跟踪运行或付费调用。付费研究默认关闭，直到阶段 5 的费用保障完成。
- 区分 Logearn 业务事实、GSC 观测与 OpenSEO/DataForSEO 第三方估算；不推断因果关系或把不可用当成 0。
- 插件数据不可信：输入输出按能力白名单和 schema 限制，防止凭据、隐私、过大内容和第三方指令进入模型。
- 注册表、能力目录与执行检查必须在 API、Worker、任务恢复等全部入口一致生效；执行时重新验证授权。
- 数据库迁移遵循现有迁移体系；不可把 SQLite 单进程锁当作跨 Worker 的费用保障。
- 非破坏性增量实施；任何需确认的部署、真实付费调用和外部写操作按现有授权及项目规定处理。

## 实际代码入口

- `backend/src/ai/business/tools/registry.js`：现有工具目录、输入和 scope、调用与证据处理。
- `backend/src/ai/business/foundation.js`：任务能力目录、补充调查和恢复。
- `backend/src/ai/business/runner.js`：模型补充调查、trace 与恢复；`modelTransport.js` / `modelEvidence.js`：模型安全投影。
- `backend/src/ai/business/evidence.js`、`metricRegistry.js`：证据 owner 隔离、指标及引用校验。
- `backend/src/ai/growth/skills.js`、`planner.js`：技能和静态工具规划。
- `backend/src/ai/growth/budget.js`：现有模型轮次预算，不是第三方美元预算。
- `backend/src/ai/growth/gscService.js`、`gscClient.js`：现有 GSC 连接和快照，保留其语义。
- `backend/src/routes/growthAgent.js`、`backend/src/routes/aiAnalysis.js`：公开 API / Growth 任务入口。
- 测试参照 `backend/test/growthSpecialistTools.test.js`、`backend/test/gscService.test.js` 及现有业务 Agent 测试。

新模块路径在实现时按现有目录习惯确定；稳定接口在各阶段提交中明确记录，避免仅为抽象引入空层。

## 阶段 1：能力目录和兼容层

**交付：**受控能力注册接口；旧工具通过兼容层继续工作；不引入任何实际外部服务调用。

- [ ] 写测试：旧工具 ID、schema、scope、输出和现有 SEO/KOL 能力不变；可注册一个测试连接器；重复 ID、无效版本/schema/声明被拒绝。
- [ ] 设计能力描述：命名空间 ID、版本、简述、输入/输出 schema、作用域、权限类型、费用类别、执行器及安全投影。费用声明和只读声明不是授权。
- [ ] 把现有 `listCapabilities` 和执行路径接入兼容入口，保留旧调用契约；禁用能力不显示也不可执行。
- [ ] 运行相关测试与现有 Growth Agent 回归；记录接口和变更，独立提交。

**验收：**增加项目内测试连接器不需修改 Agent 核心调用分支；无现有功能回归。禁止大规模无关重构。

## 阶段 2：网关、用户授权与任务约束

**交付：**统一执行入口，能力授权同时作用于目录展示和实际执行。

- [ ] 写测试：A/B 用户、连接和项目隔离；未启用或未授权能力、伪造能力名/参数/项目、未被本次任务允许的调用均拒绝。
- [ ] 在可信服务端创建任务可用能力集合；执行时重验 owner、连接归属、资源 scope、任务许可和状态；禁止从模型输入获取外部凭据或地址。
- [ ] 对 `foundation.prepare/resume`、`growthAgent` API、后台 Worker 和其他入口统一治理；已保存结果可重放，重新发起调用前重新验证授权及任务租约。
- [ ] 实现有界参数与结果、超时、并发和规范化错误；区分拒绝、配置缺失、服务不可用和预算不足。
- [ ] 测试断权、重启/恢复、超时和外部失败；验证现有工具 scope/水位不退化；独立提交。

**验收：**隐藏能力不等于授权；伪造请求和跨用户读取均无法绕过服务端。外部故障不会让内部数据被误当作 0。

## 阶段 3：证据与模型投影

**交付：**外部数据可追溯、可由 Agent 安全引用，且可与内部证据并存。

- [ ] 写测试：模拟排名结果经过存档、`statView`、补充调查结果及恢复后，模型仍能看到必要关键词、排名、时间与限制，最终结论能引用证据 ID。
- [ ] 设计并实现有界证据外壳：provider、能力/版本、owner/连接、采集时间、查询范围、来源类型、覆盖/截断、警告及费用状态；复用现有证据 owner 校验和不可变属性。
- [ ] 建立按能力的最小输出投影，保留业务有用字段；移除密钥、个人资料、无关文本和过大数据；外部字符串作为不可信数据。
- [ ] 分别记录内部事实、GSC 观测和第三方估算；数据缺失、零排名、未找到和未查询保持不同语义。
- [ ] 测试跨用户引用、过长字段、恶意文本、缺失值和最终 claim 校验；独立提交。

**验收：**不能仅在存储层看到数据；模型传输和最终报告的端到端测试必须证明数据和来源可用。

## 阶段 4：OpenSEO 免费只读连接器

**交付：**通过自部署 OpenSEO MCP 读取授权项目的已有排名跟踪配置与结果。

- [ ] 根据实际部署版本检查 OpenSEO `get_rank_tracker` MCP 协议、认证与结果 schema，锁定受支持版本并说明兼容方式。
- [ ] 写本地模拟 MCP 测试，覆盖 initialize/会话、工具调用、认证失败、超时、分页、异常响应、项目隔离和连接关闭；确保不会调用 `run_rank_tracker` 或研究工具。
- [ ] 在服务端设置连接 URL、密钥和 owner/项目映射；限制合法目标，禁止未授权地址和重定向绕过；凭据从不返回 UI、日志、模型或证据。
- [ ] 读取保存的排名及最近检查时间；区分尚未检查、结果未找到、授权失败与上游不可用，不推断排名下限。
- [ ] 通过网关及阶段 3 投影形成证据；添加连接配置和运维文档，独立提交。

**验收：**模拟服务端到端测试通过；关闭或未配置 OpenSEO 时现有 GSC/Growth 正常。真实连通、授权、数据新鲜度需在自部署环境另行验证并记录。

## 阶段 5：外部数据费用与关键词研究

**交付：**具备安全费用边界后，可受控使用一项付费关键词研究能力。

- [ ] 先研究当前 OpenSEO 工具及 DataForSEO 实际计费、费用估算与幂等能力；记录无法可靠硬封顶的情形，不把本地预估表述为供应商保证。
- [ ] 写测试：未配置/超预算不发起请求；多 Worker 并发原子预留；进程崩溃、超时、供应商已收费但响应丢失、重复调用和恢复不得盲目重试或将未知费用视为 0。
- [ ] 用共享持久化数据库实现按 owner/工作区、连接、能力、任务与周期的费用策略和预留/结算/未知状态；默认关闭。确定并记录币种、日界线和账单对账办法。
- [ ] 只开放 `research_keywords` 的受限输入、投影和项目绑定；明确国家、语言、估算来源、调用时间、结果上限及费用。
- [ ] 记录供应商实际费用；无可靠回执时保持未知并阻止不安全重试；验证项目授权与缓存隔离。
- [ ] 模拟并发与故障测试，条件允许时做真实数据库集成测试；真实付费验证需明确记录，不由测试自动触发；独立提交。

**验收：**无预算无外呼；未证明供应商硬限额时不承诺绝对费用上限。可同时引用关键词估算和 GSC 事实但不能混淆定义或推断因果。

## 阶段 6：动态规划、管理与运维

**交付：**已授权能力能被相应 Growth 技能发现；用户可查看连接状态和使用限制。

- [ ] 测试按任务目标、scope、用户、插件连接和预算筛选能力；执行时仍重验授权。变更 `planner.js` 中模块加载时固定 `supportedTools` 的模式。
- [ ] 在 SEO 技能中组合现有 GSC、内部业务数据和已启用 OpenSEO 能力；限制模型上下文工具数量，不因插件增加无限膨胀。
- [ ] 完成最小管理入口：连接状态、可用能力、错误、启停与费用状态；密钥仅接受安全的服务端配置或项目认可的安全管理方式，绝不回显。
- [ ] 验证插件故障降级、连接撤销、运行中任务策略、并发与恢复；以第二个不同协议的测试连接器验证不修改 Agent 核心即可接入。
- [ ] 编写配置、权限、备份、升级、故障排查与验证手册；完成前后端相关测试和端到端模拟；独立提交。

**验收：**连接后 SEO 任务可选择并实际使用能力；断开后新任务不可使用；内部能力不受外部服务故障影响；模型和 UI 的状态一致。

## 每阶段交付与 Review

每个阶段的 PR 或提交说明提供：变更范围、具体行为、测试命令与结果、已验证/未验证项目、迁移与回滚方式、费用和权限风险。不要包含凭据、用户数据或真实 API 响应敏感内容。

Review 重点：实际执行是否绕过网关；跨用户/工作区隔离；模型是否真的接收到安全且可引用的数据；重启/超时是否重复付费；并发预算是否跨进程有效；旧工具与 GSC 是否回归；自部署真实验证与模拟测试是否区分。
