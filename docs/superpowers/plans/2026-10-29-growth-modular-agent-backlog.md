# AI Growth Agent 增长分析模块化实施清单

> 给实施 AI：以本清单为任务范围，先核对当前 Git 状态、适用的 AGENTS.md 和现有代码。以代码及真实运行证据为准；不要把 mock 测试当成真实外部连接或生产验收。本清单不授权提交、推送、部署、开启付费调用或修改外部服务。

**目标：**在 `seo` 分支已有能力目录和网关上，把现有增长分析封装为输入输出稳定、版本化、可扩展的只读模块；让 AI 根据目标和问题组合调用、追查证据、比较优化机会，并保留人工分析原有行为。

**当前基线：**编写时 `seo` 与 `origin/seo` 一致，HEAD `4c33f04`。执行时重新确认，不要重置、覆盖或提交用户改动。已有计划参考 `docs/superpowers/plans/2026-10-29-growth-plugin-openseo.md`；本清单扩展其业务模块和决策能力，并不声称原计划所有阶段已线上验证。

## 全局边界（每项任务均适用）

- 不修改现有人工 SEO、渠道、推荐、注册、漏斗、路径、留存、交易、分群等页面、接口行为、业务查询、筛选语义或指标口径。以 AI 专用适配器复用现有服务；如不可避免要动共享代码，先证明原行为不变，无法证明则停止该共享改动并报告。
- 不把 AI 接入当作重写、迁移或删除原业务模块；不重定义北极星。用户可继续独立完成人工分析。
- AI 默认只读；模块输出为证据，建议和机会存于 Agent 专用对象。外部动作、业务写入、自动发布及修改生产配置不在本任务范围。
- 缺失、未观测、未成熟、来源未知、查询失败与数值 0 分开；首次观测不等于首次使用或新注册，推荐绑定不等于新增获客，交易量不等于收入，相关性不等于因果。
- 区分 LogEarn 事实、GSC 观测和第三方估算；保留来源、时区、日期窗口、指标版本、采集水位、覆盖和局限，不把不同口径强行归因或相加。
- 继承现有 owner 隔离、权限、只读、调用预算、证据、任务恢复和付费防重。敏感明细不直接进入模型；模块失败不扩大权限，也不能默认重放未知付费请求。
- 外部能力默认关闭；只接项目内经审查的适配器。不实现任意代码安装或执行、插件市场，不擅自配置凭据或触发外部付费请求。
- 写针对行为的测试并运行适用检查；每项记录失败、跳过和环境限制。保留真实未验证项，不将合成样本或模拟服务报告为线上成功。

## 统一契约（先实现可用的最小版本）

每个模块有稳定 `moduleId`、语义版本、说明和一组命名能力。每个能力声明：用途与限制、严格输入 schema、支持的范围、只读及费用属性、授权要求、执行限制和输出 schema。服务端解析 owner、连接及资源范围；模型或客户端不能指定任意服务地址、密钥或越权对象。

统一结果外壳包含：`status`（成功、无数据、未配置、无权限、不可用、参数错误、预算不足）、模块/能力及版本、请求期间和范围、证据 ID、来源类型与指标定义版本、采集时间/水位、覆盖与成熟度、警告、有限的统计数据。实际字段采用现有项目命名习惯；业务负载可因模块不同而不同，未知允许 null 且须有原因。模型输出只包含最小必要的聚合投影。已保存报告固定模块版本和证据，不因升级静默改变。

统一契约不是要求每个模块只暴露一个工具；模块可提供多个具体能力。适配器与人工调用共享现有业务服务，不复制 SQL 或另建口径。

## P0：安全边界和可靠调用

### 任务 1：建立人工分析回归基线

- [ ] 清点人工 SEO、渠道、推荐/邀请、登录、漏斗、路径、留存、产品链、交易和分群的入口、参数和现有数据服务，记录关键口径及快照/水位。
- [ ] 用固定测试数据和现有测试建立可重复基线；比较筛选、分母、数值、状态及错误，不依赖变化中的实时数据库作严格相等比较。
- [ ] 后续每个阶段运行相应基线；记录无法覆盖的真实环境部分。
- **验收：**固定样本下改前与改后人工接口/服务和页面关键行为相同；至少 SEO、渠道、漏斗、路径、留存均有可运行回归；发现非预期变化不得通过。

### 任务 2：模块契约与目录

- [ ] 检查 `backend/src/ai/business/tools/capabilityCatalog.js`、`registry.js`、`foundation.js`，复用现有能力目录，增加模块级描述和能力到模块的映射；保留现有 tool ID 与已保存任务兼容。
- [ ] 实现上述契约的严格校验、版本、结果外壳及有界模型投影；不能信任外部输出或只靠描述声明权限。
- [ ] 验证注册、发现、输入输出、取消授权、跨 owner、范围限制、超时和旧上下文恢复。
- **验收：**SEO 与漏斗两个不同数据形态能通过同一契约；旧工具及历史任务不退化；未知、空、失败分开；人工业务接口保持基线。

### 任务 3：修复真实工具调用错误

- [ ] 在 AI 能力描述中提供准确的 `scope.source`、合法漏斗步骤、范围和示例；拒绝不支持的筛选，勿修改底层业务规则。
- [ ] 返回安全、具体的字段错误与允许值，避免无效请求反复消耗轮次；记录调用和失败状态。
- [ ] 用已观测案例复现：`filters.source=direct` 及非法步骤被拒；引导生成合法 `scope.source` 调用。来源范围和权限校验不能绕过。
- **验收：**合法请求可执行；错误参数得到可操作反馈且不扩大权限；同类错误可识别；现有人工调用无变化。

### 任务 4：证据引用与可恢复诊断

- [ ] 保留 `backend/src/ai/business/evidence.js` 的证据和 owner 校验，定位不匹配的结论、证据及字段；错误信息不得泄露不必要内容。
- [ ] 定义允许引用的原始值及带来源的派生值，兼容现有证据记录；不因提升成功率而接受无依据数值。
- [ ] 使用真实失败记录的脱敏重放或等价固定样本，检查错误、纠正、调用上限、断点和最终失败提示。
- **验收：**错误值仍被拒；合法引用可通过；连续校验失败可定位，不能制造成功；历史任务恢复和其他模块证据不退化。不得将已有内容专项失败归因于某种具体错误，除非重放证据证明。

## P1：首批业务模块（只读适配）

各模块先定义最小能力、输入输出、口径与边界，再编写适配器及测试。保留底层实现与人工入口；返回证据 ID、时间范围、覆盖及状态。不要将模块表述为真实数据已接通，除非有实际验证。

### 任务 5：SEO 模块

- [ ] 包装现有 `get_seo_performance` / GSC；保留可选 `openseo.saved_rankings`，GSC、第三方排名独立标明来源。
- [ ] 输入站点及期间；输出搜索聚合、页面/查询、排名快照的可用部分、时区与覆盖；GSC 日期与 Bangkok 业务日期不同须标明。
- **验收：**未配置 OpenSEO 时 GSC 和其他模块仍可用；未检查、未找到和零分开；不得计算未经证实的 SEO 到注册归因；人工 SEO 回归通过。真实连接另验。

### 任务 6：渠道与拉新模块

- [ ] 封装已有 `get_channels` 和相关增长数据，提供来源、人数、成熟分母、激活/回访观察及来源未知情况。
- [ ] 区分首次观测和注册；`registered_users` 尚未适配时明确不可用，不另写业务指标。
- **验收：**固定来源样本与现有人工分析一致；来源未知和注册缺失不伪造；跨来源结果标明窗口与口径。

### 任务 7：推荐与邀请模块

- [ ] 审核已有 `referral`、`invite-conversion` 和注册关联服务，选取已存在的只读聚合封装；不改变关系定义。
- [ ] 输出邀请关系、可观测注册/转化及覆盖、成熟情况；必要时说明顺序未知和绑定不等于新客。
- **验收：**适配结果与现有人工分析固定样本一致；未关联数据保持未知；不得把成员明细无界发送模型。

### 任务 8：登录、激活、漏斗与路径模块

- [ ] 封装已有登录转化、`get_funnel`、`get_paths`、`get_product_chain` 的可用能力；公开合法步骤、范围及时间窗口。
- [ ] 输出阶段人数、分母、成熟/待成熟、未关联、路径和事件覆盖；功能结果缺失时返回不可用。
- **验收：**direct 案例使用合法参数；人工漏斗与路径结果与基线一致；未观测不等于未使用，不能以路径相关性断言产品原因。

### 任务 9：留存、核心使用与分群模块

- [ ] 封装 `get_retention`、`get_segments` 和 `query_metrics` 中现有北极星/周核心能力；保留独立指标定义和目标版本。
- [ ] 输出成熟分母、回访人数/比例、人群范围、观测窗口、覆盖及水位；只提供授权的有界聚合。
- **验收：**未成熟为未知；无成熟分母不可计算；固定队列结果与现有人工留存、分群和核心指标一致。

### 任务 10：数据质量与业务目标模块

- [ ] 封装现有 `check_data_quality`、证据存储及已存在的目标上下文；标明数据水位、缺失、身份和覆盖限制，目标缺失显示未知。
- [ ] 所有模块引用同一目标版本与证据外壳，不将分析事件或快照 ID 宣称为强一致全源水位。
- **验收：**缺源/水位未知不会产生假零或业务结论；可回溯目标、证据版本和授权范围；旧记录仍可读取。

## P2：Agent 跨模块调查与优先级

### 任务 11：调查规划与按需组合

- [ ] 在 `backend/src/ai/growth/planner.js`、`backend/src/ai/business/foundation.js` 的现有框架上，增加主动全链路扫描与用户指定问题两种模式；根据授权、范围和预算选择可用模块能力。
- [ ] 每个计划记录欲回答的问题、所选能力、调用结果、缺失和必要补查；禁止模块不可用时把缺失当成结论。
- [ ] 保留原有专题任务及历史恢复；调用上限、权限和付费防护生效。
- **验收：**固定案例能调用 SEO、渠道和漏斗至少三个模块并根据结果补查；一模块失败其余可继续，输出明确缺口；定向问题不强制调用全部模块。

### 任务 12：统一机会池

- [ ] 建立 Agent 独立机会对象：问题、模块与范围、目标版本、证据 ID、影响范围/未知、假设、可信度、预估投入/待估算、最小行动、验证指标、状态及历史。
- [ ] 按 owner、对象、范围、问题及证据窗口设计去重/更新；目标版本变化保留历史，用户可记录负责人和状态。
- **验收：**跨模块机会同池可追溯；持续问题更新而非每日重复创建；跨 owner 拒绝；缺失影响和投入明确未知。

### 任务 13：机会比较与决策输出

- [ ] 比较目标关联、影响范围、改善空间、可信度和实施投入；明确优先调查、优先实施、暂缓和不可比较的原因。
- [ ] 不以未经依据的数字生成 ROI，不以评分掩盖缺失；记录人工作出调整的理由。
- **验收：**固定跨模块案例提供可解释排序及反例；投入或影响未知时不虚构精确值；每个建议链接有效证据与可验证指标。

### 任务 14：AI Growth 工作台

- [ ] 只修改 Agent 工作台：展示机会榜、排序依据、状态、证据、调查过的模块、缺口与建议；提供用户提问和定向调查。
- [ ] 保留历史分析、审批及复盘入口；加载、失败、缺数据状态清晰。
- **验收：**用户能从榜单下钻至证据和调查过程；历史报告可读；人工业务页面不变。检查桌面及移动端基本可用、键盘操作及错误状态。

## P3：扩展、主动扫描及闭环

### 任务 15：第二个不同来源的模块验证扩展性

- [ ] 在不修改 Agent 核心执行/规划代码的前提下，使用独立受审适配器和测试服务验证与 OpenSEO 不同来源或协议；生产外部/开源项目由业务需求、许可证、部署和费用另行选定。
- [ ] 测试注册、授权、故障、撤销、证据、版本和输入输出；禁止运行未审查代码或付费外呼。
- **验收：**通过目录接入和调用第二个模拟/本地受控模块；外部项目真实部署未验证时明确标记，不虚报真实接入。

### 任务 16：定期扫描、执行及复盘

- [ ] 复用现有调度、预算和任务工作流；定期更新机会和数据缺口，无重要变化时不重复生成建议。
- [ ] 人工接受后可转已有待办，记录执行动作、时间、负责人和实际投入；观察期成熟后复盘约定指标，保留混杂因素。
- **验收：**重复扫描幂等；未执行不计入效果；缺源不会变成假业务问题；前后变化不自动宣称因果；不自行触发对外动作。

### 任务 17：最终验收与交付

- [ ] 跑相关 Agent、模块、权限、证据和人工分析基线测试；记录命令、通过/失败/跳过和真实环境限制。
- [ ] 使用固定案例验证至少三个模块组合、失败降级、越权拒绝、证据回溯、机会排序、历史任务兼容；验证第二种模块接入不改 Agent 核心。
- [ ] 在已授权真实环境下只读核对数据可用性、实际模块配置、Worker 和结果；真实模型调用及外部付费服务须有明确授权和预算。观察期未成熟时复盘标记待完成。
- [ ] 输出模块清单、版本/能力/状态、接口契约、部署依赖、迁移及回滚、测试结果、未验证事项；不得擅自迁移、部署或推送。
- **验收：**人工分析无非预期改变；每个已交付模块有可运行契约测试；跨模块分析与机会决策可追溯；生产未验证项明确列出。

## 建议执行顺序

1. 任务 1—4：保护人工分析并修复 Agent 调查可靠性。
2. 任务 5—10：逐个交付首批只读业务模块，每个模块独立验收。
3. 任务 11—14：跨模块调查、机会池与工作台。
4. 任务 15—17：验证扩展性、调度和完整闭环。

本清单不要求将内容、X 关注者、KOL、交易、活动、合作成本等全部在首批实现；后续沿相同契约逐个接入。它们现有能力的可用性和数据局限应在模块目录中标明，不能因为没有适配就声称已可由 Agent 完整使用。
