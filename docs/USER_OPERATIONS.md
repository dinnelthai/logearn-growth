# 统一用户详情与运营工作台

入口：运营工作台 → 待办；用户列表、活动成员、KOL成员及分析下钻均可打开注册账号的统一用户详情。

用户详情包含账号、当前账号可见的活动/KOL标签、所选期间使用与交易、资产线索、分页时间线和跟进记录。列表保持原状态，详情关闭不触发列表重新圈选。跟进支持下一步、检查时间、完成与重新打开。KOL手动标签的单人维护沿用账号验证、owner及版本冲突检查，自动关联账号标签不能从用户侧移除。

工作台汇总KOL到期跟进、活动结算及用户跟进。活动截止后不足24小时仍为等待，实际结算保留原来的时间与来源完备性检查。KOL和活动行跳转到原对象处理；用户待办可直接标记完成。团队共享、自动通知、批量触达尚未接入。

预约活动单列「预约启动」：未来计划显示未到期，到时仍未固定名单则进入到期待办，显示等待/失败原因；启动后预约事项消失，进行中活动计数增加。尚未启动的预约不进入结算待办，归档时暂停。详情可修改未来计划或到时手动重试，后台运行时自动检查并在恢复后补处理。

接口均需登录：

- GET /api/users/:id/profile：start、end、snapshot_id或cache_id、event_offset。注册ID支持数字或user:前缀；作业ID必须属于当前登录账号。事件每页100条，具有下一页标记。
- POST /api/users/:id/followups：content、next_step、due_at（毫秒或null）。校验实际注册账号；本地持久化。
- PATCH /api/user-followups/:id：status=open|done；按owner隔离，完成保留原文与时间。
- GET /api/workbench：任务、类型、计划时间、状态及各类汇总。
- PATCH /api/crm/kols/:id/members：user_id、action=add|remove、expected_updated_at；保持原档案字段及修改记录。

数据口径：分析次数仍为已观测事件数，交易使用统一已验证身份和已知USD金额；缺记录不等于未使用。用户详情显示当前选定窗口，正式邀请贡献仍在CRM按绑定后口径计算。旧活动冻结与用户当前画像为不同记录版本，更新用户数据不会重写活动结算。

## 运营线索转为固定人群任务

分群应用筛选后，在「将这批用户加入运营待办」中填写标题、负责人备注、优先级、下一步和下次检查时间。创建时从当前账号的分析结果读取完整去重名单，固定原始条件、期间、快照及分析/交易基线；客户端不能自行替换名单。每任务最多5000人，空人群及基线来源不完整时拒绝创建。同一分析结果重复提交返回原任务。

任务持久保存在本地后台 operation_tasks / operation_task_history，分析缓存过期或服务重启不会丢失名单及基线。当前账号隔离；负责人是文本备注，不授予其他账号权限。状态支持待处理、处理中、已完成，完成时须填写处理记录；可以重新打开，历史记录始终保留。更新使用expected_updated_at防止并发覆盖。

工作台增加人群待跟进及人群任务视图；未排期不算到期，处理中任务仍算未完成，完成后移入历史。详情可重新分析原始固定名单，使用当前快照和原始统计期；继续观察从任务创建至事件数据截至、最长最近366天。数据截至未超过创建时间时显示继续观察；来源失败保留未知，历史基线不更新。两个窗口长度不同，不直接相减或解释为因果提升。

新增鉴权接口：POST /api/operation-tasks（cache_id及任务字段）；GET/PATCH /:id；GET /:id/audience；GET /:id/review。修改不接收名单或基线覆盖。GET详情只传名单数量，通过audience接口取得完整固定ID。跟进内容、名单及基线均只写本地管理库，远程业务数据查询保持只读。

## 用户详情快捷动作与统计期（2026-10-15）

详情可搜索当前账号的活动，添加/移除活动标签，或将该用户追加到尚未截止的活动新批次；后者保留既有固定名单并按现有服务端规则校验、去重和固定基线。可直接保存该用户为静态人群。标签动作与监控入组分别说明，已在历史批次中的用户不能重复追加。

用户详情、首页、KOL、效果对比、分群和推广报告共用UTC+7统计期计算，最近N天包含数据截至日、end为数据截至+1；自定义使用开始含/截止不含。用户详情可延长历史，事件分页和使用/交易共用窗口；跳转分析保留当前名单、窗口和快照。固定人群/任务与保存报告使用自己的原始窗口，活动预约与生命周期、推荐绑定批次/传播观察窗保持独立；全平台路径保留原有7天查询上限。当前选择在本次页面会话中继承，重新载入恢复默认。
