## 四、分阶段实施计划

### Phase 1: Redis 缓存 (1-2 天)

**目标**：降低 LLM 成本，加速数据查询

**任务清单：**
- [ ] 安装和配置 Redis
- [ ] 实现 LLM 响应缓存
- [ ] 实现数据查询缓存
- [ ] 集成到 LLM 客户端
- [ ] 添加缓存管理 API
- [ ] 测试缓存命中率

**验收标准：**
- LLM 响应缓存命中率 > 40%
- 相同查询响应时间降低 > 80%
- 缓存相关接口正常工作

**成本节省估算：**
- LLM 调用减少 40-60%
- 每月节省 ~$20-50

### Phase 2: Bull 任务队列 (2-3 天)

**验收标准：**

**价值：**
- 用户不用等待 AI 分析

## 七、风险和挑战

### 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Redis 宕机 | 缓存不可用 | 降级到直接调用（fail-open） |
| 任务队列堆积 | 任务延迟 | 监控告警 + 自动扩容 Worker |
| WebSocket 断连 | 用户体验下降 | 自动重连 + 降级到轮询 |
| 向量检索慢 | 响应慢 | 建索引 + 缓存热门查询 |

### 运维挑战

| 挑战 | 解决方案 |
|------|----------|
| 多个组件管理复杂 | 使用 Docker Compose 统一管理 |
| 成本监控困难 | 实现成本追踪和告警 |
| 故障排查困难 | 统一日志 + 监控面板 |


## 十一、常见问题

### Q1: 必须全部实现吗？

**A:** 不必须。最小可行方案只需要 Phase 1 + Phase 2（Redis + Bull），就能获得：
- 降低 LLM 成本
- 异步任务处理
- 定时任务

其他功能可以后续迭代。

---

### Q2: 成本会不会很高？

**A:** 初期成本不高：
- Redis: $0-10/月（小规模可用免费层）
- Qdrant: $0-20/月（自建或小规模免费）
- 主要成本是 LLM API，但缓存能节省 40-60%

---

### Q3: 开发难度大吗？

**A:** 中等难度。如果你：
- ✅ 熟悉 Node.js
- ✅ 用过 Redis
- ✅ 理解队列概念

那么 Phase 1-2 很快（3-5 天）。

Phase 3-4 稍难，但文档很详细。

---

### Q4: 可以用其他技术栈吗？

**A:** 可以替换：
- Redis → Memcached（但功能少）
- Bull → BullMQ / Celery / RabbitMQ
- Socket.IO → 原生 WebSocket / SSE
- Qdrant → Pinecone / Weaviate / Milvus

但建议按文档先实现，稳定后再替换。

---

### Q5: 数据库表在哪里创建？

**A:** 已在 `backend/src/db/schema.sql` 添加，运行迁移即可：
```bash
npm run migrate
```
