# 激活分析人工评测

这是离线人工评分工具，不调用模型、不读取数据库，也不作为提示词发布门槛。示例是合成数据，不代表真实模型效果。

选择同一业务问题和同一数据快照的旧版、新版分析结果。操作员先核对原始证据和调查记录，再分别填写布尔评分；无法判断时留空，不得当作通过或失败。使用匿名案例编号，不在评测文件中放用户数据、提示词、分析原文或密钥。建议先独立审核，再对照版本，减少知道版本后的偏差。

每个结果由人工记录 `reviewer` 和 `ratings`：

- `facts`：关键数字、期间、范围和指标口径与原始证据一致。
- `evidence`：关键结论有能实际支持该结论的证据，而不仅是存在证据 ID。
- `investigation`：调查覆盖了能改变判断的主要缺口；没有必要的补查时，可评为通过。
- `action`：行动与已知证据相符，有明确的执行或验证方式，证据不足时允许建议先调查。
- `uncertainty`：明确重要数据缺口，区分观察、假设和因果。

复制 [合成示例](../../backend/test/fixtures/activationReviews.synthetic.json) 的结构，在受控位置填写案例。每个案例的 `baseline` 和 `candidate` 分别记录审核人及五项评分；缺少审核人或任一评分的案例会列入 `incomplete`，不计入对比。案例 ID 必须唯一。

```bash
cd backend
node scripts/compareActivationReviews.js /path/to/reviewed-cases.json
```

输出每项通过数、通过率、改善和退步的配对案例数。先积累真实、经过人工核对的案例并保留评测版本，再解释结果；样本少或案例不具代表性时，不能由通过率推断线上效果或收益。
