# Growth events：采集检查点方案与证据边界

2026-10-31；仅设计和离线结构校验，不会改变 Hologres 状态或启用调度。

当前分析仓库不包含线上接收服务。邻近产品仓库 `logearn-web` 的 `src/plugins/logearn_growth/transport.ts` 以 25 条或 5 秒批量 POST；失败事件缓存在 localStorage，容量 500，超出会丢弃最旧项；Beacon 接受排队不证明服务端持久化，HTTP 2xx 也不证明逐条持久化或业务受理。信封 `event_id` 在重试时复用；接收端实际去重、队列落盘、部分失败、历史回填与重试状态尚未核验。客户端离线或数据被清理时，服务器可能不知道存在遗漏。

分析端 Hologres 按 `server_ts <= snapshot_cutoff` 限制已入库到达；`client_ts` 是设备事件发生时间，受客户端时钟影响；`server_ts` 是服务端记录的到达时间；`snapshot_cutoff` 是查询取数上界。它们都不能证明某个事件时间之前没有漏报或迟到。只读元数据检查没有发现与增长事件采集相关的明确检查点、回填或失败水位表；这仅是当前凭据可见范围，不证明上游系统没有此类记录。`hologres.status()` 保留 `history_complete=false`、`events_complete_through=null`。

北极星 SQL 使用已观测身份与筹码峰事件：匿名标识保存在浏览器本地，不等于跨设备用户；`eventsCte` 仅在单个匿名 ID 唯一关联账号时归并。首次分析需要完整的更早历史，回访分类依赖该首次时点；身份冲突、无登录关联、不同设备及历史缺口都会影响去重。不能把历史首条事件当作真实首次。

## 最小可实施的上游协议（待采集系统实现）

1. 接收服务按原始 `event_id` 持久化幂等；对每个 batch 返回逐条持久化确认、重复、可重试或永久失败，失败与重试队列可追踪且不可静默丢弃。客户端保留未获确认事件，对本地容量溢出和 Beacon 未确认计数。定义离线/丢设备边界，不能承诺不可观测行为全量。
2. 针对明确版本的生产来源与分区清单，采集端/队列持久化接收和消费 checkpoint；记录提交的 offset/批次、确认时间、待重试与死信计数，以及独立对账后的事件时间闭合边界。分区变更、重放、回滚与乱序须有版本或代次；仅所有分区覆盖且失败、未决重试均处理后取最小水位。只用 offset 或最大事件时间不足以推导完整。
3. 历史回填提供明确起点、数据源/范围、批次/偏移清单、对账结果、完成时间和不可恢复缺口；单次回填成功不自动证明上线前历史完整。为首次/回访指定可信历史起点，覆盖不足的 cohort 保持未知。
4. 由独立可核验的受控只读来源提供版本化 checkpoint，证明生产者身份、数据源、分区集合及来源链；检查及时性、时间先后、失效与撤销。客户端采集缺陷和历史缺口单列，不能用结构格式或人工布尔值代替来源验证。
5. 先影子读取并与采集日志、队列、目标表和重放演练对账，再经数据负责人确认范围及 SLA，才讨论接入 `hologres.status()`；部署、数据库表及回滚须另行设计。源权限、日志缺失、过期、异常分区、积压或失败时继续 fail closed。

## 可独立验证的代码

`backend/src/data/ingestionCheckpointContract.js` 是纯结构检查器：对显式分区清单、观测时间、历史起点、回填声明、分区水位、待重试及失败保守校验，候选水位取分区最小值。它不访问数据库、不校验签名或权威性、不接入运行时，不会设置真实完整性状态；即使结构合格也返回 `contract-ready-unverified`、`sourceVerified=false`、`historyComplete=false`。对应测试覆盖缺失/重复分区、错误时间、过期、失败和重试。
