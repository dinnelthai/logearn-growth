# LogEarn Growth Strategy 1.0

> 版本：1.0  
> 日期：2026-11-06  
> 适用范围：LogEarn 产品增长、市场增长、商业化及 Growth Agent 决策  
> 战略状态：经营方向已定义；目标用户、渠道效率、留存驱动和商业模型仍需真实数据验证  
> 重要原则：本文件定义战略假设与决策规则，不替代正式指标注册表、数据证据、工具权限或生产状态。

## 0. 执行摘要

LogEarn 的增长目标不是单纯增加访问量、注册量或交易量，而是建立一套可持续的经营系统：

**让目标交易者通过筹码分析认识 LogEarn，通过持续的研究能力形成使用习惯，在信任和产品能力成熟后自然转化为交易与收入。**

战略主线：

1. **市场切入点：** 以 Meme / Token 交易者的筹码分布研究需求切入。
2. **核心产品入口：** Chip Distribution / 筹码峰。
3. **深度价值：** Holder、大户信息、AI Strategy、钱包与链上交易能力。
4. **核心用户：** 已有链上交易经验、持续研究 Meme / Token 的活跃交易者。
5. **增长方式：** 内容教育、搜索需求、X 实时市场讨论、KOL 和社群共同获客；产品体验和复访机制承担激活与留存。
6. **商业闭环：** 分析用户是核心经营对象；真实交易用户、交易量和可核验平台收入是独立商业结果。
7. **经营原则：** 先恢复可靠性与信任，再放大获客；先找到留存驱动，再扩大渠道投入。

当前不设未经基线验证的新增用户、转化率、留存率或收入目标。先建立可信基线，再由经营者批准目标。

## 1. 战略定位

### 1.1 产品定位

LogEarn 是面向 Meme / Token 交易者的去中心化研究与交易平台，以筹码分布为核心分析入口，连接 Holder / 大户结构、AI 策略和钱包交易能力，帮助用户理解 Token 的持仓结构与市场参与情况，并在需要时完成链上操作。

这是一项战略定位，不代表所有能力在任何时间都已稳定可用。Agent 必须先检查当前产品状态和数据覆盖，再描述可用能力。

### 1.2 核心价值主张

**看懂筹码分布，理解持仓结构，再决定如何行动。**

LogEarn 不应承诺收益、预测必涨必跌或暗示使用工具就能避免亏损。产品价值是提供更清晰的研究信息和操作能力，而不是替用户保证交易结果。

### 1.3 差异化假设

优先验证以下组合是否能形成真实差异：

- 筹码峰：帮助用户观察 Token 持仓分布。
- Holder / 大户：帮助用户理解持仓集中度及重要持有人。
- AI Strategy：帮助用户持续关注策略信号。
- Wallet Trading：将研究和交易操作连接起来。
- 多链支持：围绕当前已确认支持的链提供一致体验。

不能仅因为功能数量多，就宣称产品具备竞争优势。差异化必须通过用户选择原因、使用频率、留存和付费意愿验证。

## 2. 目标用户与市场切入

以下是待验证的 ICP 假设，不是已经由用户研究证明的市场事实。

### 2.1 核心用户：活跃 Meme 交易者

特征假设：
- 已经有链上交易经验，不是完全不了解钱包和 Token 的新手。
- 会反复研究新 Token、持仓变化和交易机会。
- 对追涨杀跌、筹码集中、大户行为和流动性风险有明确痛点。
- 有重复使用研究工具的潜在需求。

优先研究的问题：
- 用户在买入前最想确认什么？
- 筹码峰是否影响其研究过程？
- Holder 数据是否能解释筹码峰之外的问题？
- 用户为什么会在 LogEarn 分析后离开？
- 用户会不会为了这些能力再次回来？

### 2.2 次级用户：专业链上研究者

包括更重视 Holder、钱包行为、策略信号和多维数据的用户。重点验证其专业功能需求、使用深度和付费意愿。

### 2.3 分发伙伴：KOL、交易社群和内容创作者

这类对象首先是分发伙伴和影响者，不应与核心产品用户混为一谈。衡量合作价值时必须看其带来的有效分析用户、留存用户和可验证交易结果，而不是粉丝量或曝光量。

### 2.4 教育型用户：初级 Meme 交易者

通过内容教育逐渐培养其研究习惯。现阶段适合作为内容受众，不应在缺少产品引导和留存证据时成为高成本获客的第一优先级。

### 2.5 ICP 验证方法

结合真实行为分群、成熟留存队列、产品路径和定性访谈。建议先完成 8–12 次目标用户访谈，覆盖核心交易者、专业研究者和社群/KOL 伙伴。

必须回答：
1. 哪类用户最频繁遇到 LogEarn 能解决的问题？
2. 哪类用户最容易完成第一次有效分析？
3. 哪类用户会持续回来？
4. 哪类用户有真实付费意愿？
5. 哪类用户会主动推荐产品？

不得仅用注册量或访问量判断 ICP。

## 3. 产品增长策略

### 3.1 核心切入：筹码峰

筹码峰是当前经营北极星对应的核心产品入口。增长团队应该让用户理解它解决什么问题，并缩短从进入产品到看到筹码分布的路径。

重点：
- 首次体验时用真实、可解释的 Token 案例展示筹码分布。
- 解释筹码峰、Holder 和大户信息分别回答什么问题。
- 优先减少数据加载失败、空状态不清晰和功能入口难找等阻碍。
- 将查看、下钻、分析成功等事件分别记录，不能混为一个事件。

### 3.2 深度价值：多产品入口

AI Strategy、Chip Distribution、Holder Ranking 和 Wallet Trading 是不同价值入口，不是每个用户都必须按同一顺序经过的线性漏斗。

需要通过分群和行为路径验证：
- 哪个入口带来最多有效分析用户？
- 哪种组合与更高留存相关？
- 哪些产品行为与真实交易存在可验证关联？
- 哪些功能只是被打开，哪些功能真正形成重复使用？

### 3.3 留存产品机制

优先探索以下机制，前提是现有能力、数据质量和产品资源允许：
- 用户关注的 Token 或分析对象能够方便地再次访问。
- 重要 Holder / 持仓结构变化能形成有意义的回访理由。
- AI Strategy 的创建、开启、信号接收和信号查看形成清晰体验。
- 用户能够保存研究上下文，而不是每次重新寻找。
- 关键数据异常或不可用时，明确说明状态，不展示误导性结果。

通知和提醒必须有明确价值、可控频率和关闭方式，不以制造焦虑或诱导过度交易换取活跃。

## 4. 三个核心增长飞轮

### 4.1 内容教育飞轮

真实交易问题 → 筹码知识内容 → 用户理解分析方法 → 进入 LogEarn 完成分析 → 形成可复核案例 → 下一轮内容。

执行原则：
- 每条内容围绕一个真实交易问题，而不是单纯展示功能。
- 每条内容对应一个知识点和一个产品操作。
- 内容归因到有效分析用户，而不是停留在播放量。
- 真实案例必须说明数据时间、来源和局限，不用事后结果伪装预测能力。

### 4.2 产品使用飞轮

目标用户进入 → 完成筹码峰查看 → 理解 Holder / 策略等相关能力 → 形成关注对象或重复研究需求 → 再次进入 LogEarn。

这套飞轮需要验证复访行为和成熟留存队列。不能把产品页面浏览次数增加直接解释为用户价值提升。

### 4.3 研究到交易飞轮

用户研究 Token → 自主决定是否交易 → 使用钱包交易 → 获得可靠的交易体验 → 继续使用 LogEarn 研究与操作。

交易是独立商业结果，不是北极星指标的一部分。只有权威交易事实、身份匹配和来源覆盖足够时，才能报告用户关联交易结果。交易量不能替代平台收入。

## 5. 渠道组合与资源分配

渠道是获取目标用户的手段，不是独立的增长目标。

| 渠道 | 主要角色 | 应衡量的结果 |
|---|---|---|
| SEO | 捕获持续存在的研究问题和搜索意图 | 自然搜索带来的有效分析用户、成熟留存 |
| X | 触达活跃交易者、参与实时市场讨论 | 可归因的有效分析用户及后续行为 |
| YouTube / 视频 | 建立专业认知、教育筹码知识 | 内容带来的有效分析用户和复访 |
| KOL | 信任背书、精准分发 | 合作队列有效分析、留存和交易结果 |
| 社群 | 培养使用习惯、收集反馈 | 社群用户有效分析和成熟留存 |
| 付费广告 | 放大已验证的获客路径 | 增量有效分析用户、CAC 和回收周期 |

渠道判断规则：
1. 先确认渠道是否触达目标 ICP。
2. 再看带来的有效分析用户，而不是曝光或注册。
3. 再看成熟留存和真实交易结果。
4. 只有成本、归因和样本成熟度足够时，才比较 CAC、LTV 和回收周期。
5. 不把时间相关、点击归因或 KOL 合作记录直接写成增量因果。

在自然渠道和产品转化尚未形成可信基线前，不建议大规模扩大付费投放。

## 6. 北极星与经营指标

### 6.1 北极星

沿用经营者已确认的单一北极星：

**统计期内至少一次点击/打开筹码峰的去重有效分析用户数，对应正式指标 active_users。**

同一 user_key 在同一统计期内多次查看或下钻只计一人；跨统计期分别去重。当前事件映射为 chip_analysis_viewed 和 chip_analysis_drilldown。事件是否覆盖所有真实点击、跨设备 user_key 是否稳定，仍需真实来源验收。

### 6.2 配套指标

| 维度 | 重点指标 | 解释 |
|---|---|---|
| 获客 | 渠道带来的有效分析用户 | 不把曝光、点击和粉丝等同于激活 |
| 激活 | 注册到首次有效分析、首次价值体验 | 使用正式分母和成熟规则 |
| 参与 | 筹码峰、Holder、AI Strategy 等使用 | 多入口分别衡量 |
| 留存 | D1 / D7 / D30 等成熟队列 | 未成熟队列不算流失 |
| 交易 | 真实交易用户、完成交易数、交易量 | 与北极星分开报告 |
| 经济 | 平台真实收入、获客成本、服务成本 | 必须来自可核验来源 |

### 6.3 不允许的指标替代

- new_users 不等于新注册用户。
- active_users 不等于所有登录用户。
- 多次分析请求不等于多个有效分析用户。
- 交易意图不等于已完成交易。
- 交易量不等于平台收入。
- CRM/KOL 合作账本不等于平台交易收入。
- 无法匹配身份的交易不等于零交易。
- 未同步、未调查、查询失败和真实零值必须分别表达。

当前平台真实收入来源尚未得到验证。在正式接入并验收前，Agent 必须将平台收入标记为未知，不得推算或用交易量替代。

### 6.4 目标设定

先读取可信的历史基线、成熟分母和数据覆盖，再提出目标。目标必须由经营者确认。禁止模型自行编造增长百分比、CAC、LTV 或收入目标。

## 7. 商业化策略

商业化分为三个待验证方向：

1. **交易业务：** 通过可靠的钱包与交易体验形成平台商业收入。必须先接入真实平台收入数据，明确手续费、退款、失败交易和成本口径。
2. **专业分析能力：** 测试高级筹码分析、AI 策略、策略数量或专业功能的分层收费。保护核心激活体验，不因短期积分收入过度限制用户理解产品价值。
3. **团队与专业服务：** 未来可探索团队、社群或专业交易者服务，但需要真实需求和付费意愿验证后再立项。

定价实验必须明确假设、付费人群、功能边界、主指标、退款/投诉等护栏。不能把用户交易频率增加本身当成产品成功。

## 8. 信任与可靠性：增长的前置门槛

LogEarn 的数据和交易能力会影响用户决策，因此可靠性不是单纯技术问题，而是增长基础。

增长扩张前必须检查：
- 核心页面、筹码和 Holder 数据是否正常。
- 数据来源、时间水位和完整性是否可解释。
- 钱包连接、交易提交、确认和失败状态是否准确。
- 关键故障是否有明确公告、处理进度和用户补偿流程。
- 用户承诺与当前可用能力是否一致。

**P0 门槛：** 关键交易能力、安全、数据真实性或核心分析功能存在重大故障时，优先恢复、沟通和补救，不扩大付费获客，不发布超出实际能力的宣传。

截至本战略版本日期（2026-11-06），产品仍处于部分能力恢复阶段：最新运营公告称 10:30 后新 Token 筹码数据恢复正常，但交易和部分 K 线/筹码能力仍在恢复，预计 1–3 天完成，用户赔付将在交易钱包恢复正常后启动。此为有时效性的运营状态，Agent 每次制定行动前必须重新确认，不能将其永久写入业务事实。

## 9. Growth Agent 的经营职责

Growth Agent 不是周报生成器，也不是简单的渠道数据汇总器。它是一个以经营目标为中心、以证据为约束的虚拟 Head of Growth。

### 9.1 每日回答

1. 市场、竞争和用户需求出现了什么值得注意的变化？
2. LogEarn 的获客、激活、留存、交易和经济结果发生了什么变化？
3. 当前最重要的 1–3 个增长问题或机会是什么？
4. 哪些原因有证据支持，哪些只是待验证假设？
5. 今天最值得做的动作是什么，怎样判断它是否有效？

### 9.2 每周经营复盘

每周至少形成：
- 经营结论：本周最重要的变化。
- 核心证据：指标、范围、分母、来源、水位和覆盖。
- 关键瓶颈：对北极星或商业结果影响最大的约束。
- 根因判断：支持证据、反证、替代解释和未知项。
- 行动计划：优先级、负责人、资源、验证指标和复查条件。
- 历史行动复盘：区分建议、采纳、执行和观察结果。
- 战略修正：是否需要调整 ICP、渠道、产品重点或实验方向。

报告必须先给经营判断，再给证据和技术覆盖细节。不得平均罗列所有模块来制造完整感。

### 9.3 每个行动的标准格式

- 问题：要解决什么经营问题？
- 证据：哪些已验证事实支持？
- 假设：预计的作用机制是什么？
- 反证：还有什么替代解释？
- 行动：具体做什么？
- 负责人/资源：未知时明确标记未知。
- 主指标：只设一个主要验证指标。
- 护栏：哪些体验、质量或成本不能恶化？
- 复查条件：何时、达到什么成熟度后判断？
- 结论：继续、迭代、停止或证据不足。

### 9.4 决策优先级

优先考虑：
1. 战略匹配：是否服务核心 ICP 和北极星？
2. 影响规模：有多少目标用户或经营结果受影响？
3. 证据强度：是已观测事实还是推测？
4. 成功置信度：是否有合理的作用机制和可验证方法？
5. 执行成本：需要多少人力、预算、时间和工程资源？
6. 风险：是否影响数据可信、钱包安全、用户信任或核心体验？

可使用 RICE / ICE 作为辅助排序，但没有证据时不填造精确分数。P0 可靠性问题高于普通增长实验。

### 9.5 权限边界

Agent 可以自主读取已授权数据、补充调查、生成假设、起草报告和提出行动。低风险研究可在预算内执行。

以下事项必须取得明确授权：对外发布、向用户发送消息、真实广告预算、正式价格调整、生产配置、指标口径变更、用户权益和赔付变更，以及任何会影响真实用户的运营实验。

## 10. 90 天执行路线

阶段以产品可靠性和真实数据验收为门槛，不是固定日历承诺。

### 阶段 0：恢复与建立基线（第 1–14 天）

目标：恢复用户信任，确认产品和数据可用，再讨论规模化。

工作：
- 跟踪核心产品、钱包交易、筹码、K 线和 Holder 能力恢复。
- 完成公告、故障反馈和赔付流程的执行闭环。
- 检查核心事件、用户身份、来源水位和交易匹配覆盖。
- 建立最近 30/60/90 天的有效分析、成熟留存和真实交易基线。
- 访谈 8–12 位目标用户。
- 记录最重要的三个增长阻碍。

验收：核心能力状态可验证；关键指标口径和数据覆盖可解释；没有用缺失数据伪造增长结论。

### 阶段 1：验证 ICP 与产品价值（第 15–30 天）

目标：确认最值得服务的用户和最有效的产品入口。

工作：
- 比较不同来源和用户群的有效分析、回访和成熟留存。
- 找出高留存用户的共同使用行为。
- 分析首次进入、Token 查看、筹码峰查看和后续产品行为的断点。
- 测试一版筹码峰新用户引导。
- 明确 1 个核心 ICP、1 个次级 ICP 和暂缓投入的人群。

验收：形成有证据的 ICP 结论、产品激活问题和优先改进事项。

### 阶段 2：建立增长飞轮（第 31–60 天）

目标：让内容、产品使用和用户回访开始形成闭环。

工作：
- 持续生产筹码知识教育内容。
- 建立 SEO 主题集群和真实 Token 分析案例。
- 测试 X 内容形式和 KOL 合作队列。
- 优化首次分析体验和重复研究路径。
- 运行少量高质量实验，记录执行和成熟结果。

验收：至少找到一条有可重复证据支持的获客路径，以及一个可验证的留存改善方向。

### 阶段 3：放大已验证模式（第 61–90 天）

目标：把资源集中到已证明有效的路径。

工作：
- 放大带来有效分析和成熟留存的渠道。
- 逐步测试付费投放和 CAC。
- 验证专业分析功能的付费意愿。
- 将真实交易和平台收入纳入独立经营复盘。
- 根据实验结果更新战略假设和 Agent 的决策规则。

验收：有可追溯的渠道效率、留存证据、商业结果和下一季度资源配置建议。

## 11. 第一批实验候选

这些是候选，不是已经批准执行的任务。Agent 应先检查现有数据、产品能力和资源，再排序。

| 实验 | 假设 | 主指标 | 护栏 |
|---|---|---|---|
| 筹码峰首次体验引导 | 解释真实案例能降低首次分析障碍 | 首次有效分析率 | 页面退出、错误率、误导投诉 |
| 30 天筹码知识内容 | 场景化教育能带来高意图用户 | 内容归因有效分析用户 | 内容成本、用户质量 |
| SEO 问题型页面 | 真实研究问题能持续带来目标流量 | 自然搜索有效分析用户 | 搜索流量质量、页面体验 |
| KOL 队列对比 | 不同 KOL 的受众质量差异显著 | 每个合作带来的有效分析与成熟留存 | 成本、归因覆盖、样本成熟度 |
| 关注对象复访机制 | 保存和变化提醒能提高重复研究 | 回访分析用户 / 成熟留存 | 通知关闭率、投诉、错误提醒 |
| 高级策略付费测试 | 专业用户愿为高阶能力付费 | 付费转化及净收入 | 激活率、退款、投诉 |

## 12. 经营数据与未决问题

当前已知的系统边界必须保留：

- 现有 Business Brain、指标注册表、证据层、Growth Workspace、运营时间线、决策和学习机制应继续复用，不建立第二套分析引擎或运营系统。
- 北极星语义已由经营者确认，但真实点击事件覆盖和跨设备身份稳定性仍需验收。
- 真实 Hologres 来源完整性、水位、交易身份匹配和实际 Worker / v5 报告验收仍需单独完成。
- 平台真实收入尚无已验证的数据适配器；交易量和合作账本都不能替代平台收入。
- X、GSC、KOL 等渠道观察不自动证明站内注册、激活或增量获客。
- 社群和训练营没有专用连接器时，未记录不等于未发生。

因此，Growth Agent 的每条结论都必须标注事实、假设、未知和建议，不得用战略假设填补数据空白。

## 13. 战略复审与版本治理

每月复审以下内容：
- 核心 ICP 是否仍有最强留存和付费证据？
- 筹码峰是否仍是最有效的产品入口？
- 哪个增长飞轮真正运转，哪个只是流程图？
- 渠道是否带来高质量用户？
- 留存提升是否有成熟队列证据？
- 交易和收入是否有可靠来源？
- 当前最大的约束是否已从可靠性转向激活、留存或商业化？

任何战略变更都要记录：变更原因、支持证据、反对证据、适用范围、生效日期、版本和回滚条件。模型可以提出变更，但不能自行修改正式指标定义或业务目标。

---

## 最终经营原则

**先创造真实价值，再建立用户信任；先找到持续使用的理由，再扩大获客；先验证商业模式，再放大收入。**

LogEarn 的增长不是把流量推入一个交易页面，而是建立一套从专业认知、有效分析、持续使用到真实商业结果的长期系统。
