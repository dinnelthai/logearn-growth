# Growth Agent 架构方案（讨论稿）

日期：2026-10-27。依据当前代码审阅，不是实现承诺或生产验收。本轮只出方案。

## 目标与架构选择

建设一个了解 LogEarn 业务目标、能自主补查、能解释证据、能从实际反馈中改进的增长研究助手。沿用一个 DeRouter 模型。

三种方式：

1. 固定报告加提示词：改动少，但探索范围受固定报表约束。
2. 模块化后端 + 一个 Agent + 可组合只读工具：推荐。复用已有计算服务，明确指标口径与证据身份，同时支持动态研究。
3. 多 Agent 分工：以后在单 Agent 评估和独立任务吞吐证明有必要时考虑；当前会增加协调、上下文和费用问题。

## 保留与调整

- 保留 Hologres 分析计算、现有增长指标、业务日口径、覆盖与未知状态。
- 保留人工业务报告、运营任务和可选 AI 分离，模型不可用仍能正常查看业务。
- 保留 Bull 执行长任务、PostgreSQL 保存 AI 记录、SQLite 保存现有业务对象；第一阶段不迁库、不拆微服务。
- 明确业务对象所有者和事实来源；跨 SQLite/PostgreSQL 用稳定ID、幂等键和可重试事件衔接，不依赖跨库事务。
- 封装 analytics service，页面和 Agent 共用同一计算实现；Agent 不经过前端抓取数字，也不自行重新定义指标。
- 当前 analysisJobs 是进程内 Map/Worker，AI 为 Bull。短期统一 jobId/traceId/状态与超时传播，长期将需要恢复的研究子任务持久化；不必把所有短查询迁到 Bull。
- 现有 snapshot/cutoff 继续使用，但补充各事实源的水位与版本；多源同一个ID不等于数据库强一致快照。证据要如实记录各源截至时间。

## 分层与职责

1. 业务语义：业务目标、指标定义与版本、阶段转化、目标人群、预算、资源、活动/版本变更。
2. 事实服务：事件、注册、分析成功、交易、渠道、活动、人群、合作成本收入，统一身份和范围。
3. 证据服务：快照、指标值、分子分母、覆盖、可复现查询、报告定位与证据ID。
4. 工具服务：发现能力、获取定义、查指标、拆维度、漏斗/路径/留存、活动与人群、质量检查、知识搜索。
5. Agent 运行：计划、补查、假设验证、预算、检查点、取消、恢复、调查日志和最终交付。
6. 行动反馈：建议转既有运营任务、人工审批和执行事实、复盘和实验结果。
7. 学习评估：经验候选、验证、检索、有效期、离线评估、策略版本和回滚。

## 信息获取设计

### 结构化业务数据

第一批工具建议：list_capabilities、describe_metric、query_metrics、compare_segments、get_funnel、get_product_chain、get_paths、get_retention、get_activity、get_channel_economics、check_data_quality、get_evidence。

工具内部复用现有 analytics/data 服务；每个工具用 schema 校验维度、指标、权限、人群规模、时间范围、快照、扫描量和结果上限。工具结果过大时先返回统计和证据索引，按需分页取明细。

需要超出现有工具探索时，引入受控查询描述：指标ID、分组维度、过滤条件、窗口和比较方式，由服务器编译白名单查询。新指标只能登记为候选并经确认版本化，不能混入正式口径。

### 业务背景与非结构化材料

按需接入产品定义、增长目标、活动方案、投放支出、变更日志、运营笔记、用户反馈和外部市场背景。每条资料记录来源、业务范围、作者、发生/记录时间、有效期与权限。外部材料不能替代内部事实。

优先用数据库过滤与全文检索覆盖当前资料规模；需要语义检索再引入向量索引。当前 RAG 索引读取旧 ai_findings，需映射当前建议/复盘模型并补 owner/project 范围，不能直接照搬。DeRouter 的聊天可用不代表 embeddings 可用，需要独立确认后选用嵌入方案。

### 证据返回契约

每次结果包含 evidenceId、metricId/definitionVersion、filters、period/timezone、value、numerator/denominator、sampleSize、sourceVersions/watermarks、coverage、warnings、queryFingerprint、generatedAt 和 reportLocator。

事实、假设、行动建议分开保存。最终结论必须引用证据ID；服务器校验指标存在、数值对应和范围一致。文本推理质量再用规则、评估及人工抽查辅助检查。

## 自主探索

研究循环：读取目标和能力目录 → 检查数据质量 → 获取概览 → 建立多个可区分假设 → 选择能区分假设的查询 → 查反证和替代解释 → 决定继续或结束 → 形成带限制条件的结论。

例：活跃下降。先拆新用户、持续活跃、重新活跃和未观测回访；定位渠道/设备/版本贡献；对受影响人群查漏斗和路径；核对活动及产品变更；再决定是召回、修复产品或先修采集。结论允许“现有证据不足”。

用研究问题队列保存未解决问题、已查证据、下一查询、预期信息增益、优先级和停止条件。优先级结合目标相关性、影响规模、证据缺口、预计查询成本；这些是调度启发式，不冒充业务收益预测。

每次研究有 token、金额、查询扫描量、墙钟时间、轮数和重复查询预算。用户取消和预算耗尽要停止新调用，已产生证据保留，可恢复；复用缓存仍重新核对水位与权限。

探索大量分群时记录尝试次数，保留验证期，控制重复检验风险。搜索出的相关性作为候选，不能直接变成因果结论。

## 自主进化

进化对象：业务记忆、问题检索、工具选择、调查模板、经过评估的提示词。第一阶段不做模型权重训练。

四类持久对象：

- 业务事实：带来源和版本，不由模型任意改写。
- 调查经历：做过哪些查询、失败原因和证据。
- 经验假设：可能适用的行动、适用范围、反例和待验证条件。
- 已验证策略：经过业务反馈或实验支持的模板，明确有效期和限制。

学习状态：候选 → 待验证 → 获支持/被否定/仍未知 → 过期或被新版本替代。保留相反证据和失效原因。人工采纳不是效果证明；前后变化不是因果证明；模型自评不是验证依据。

自动记录低风险研究笔记。涉及稳定业务事实、正式口径和行动效果的记忆必须通过证据规则或人工确认。策略更新先跑固定评估集和时间留出案例，达到标准后灰度启用、记录版本并可回滚；Agent不能自行更改评分标准绕过评估。

评估维度：数值/引用正确性、范围与口径、工具选择、必要调查完成率、未知状态处理、重复建议率、实际可执行性、耗时与成本。评估不能只靠另一次模型评分，须结合程序检查、真实结果和人工样本。

## 自主权限

- 可自主读取：已授权范围内的指标、分群汇总、文档与历史证据。
- 可自主生成：调查笔记、假设、报告、待办草稿、策略候选。
- 预算内可自主执行：补查和验证实验的分析，不包括向真实用户随机施加运营措施。
- 对外消息、真实预算、生产配置、正式指标口径和用户权益变更，走明确授权的执行流程。执行能力与研究能力分开注册。

所有文档、外部网页和用户反馈作为资料，不作为可覆盖系统权限的指令。

## 实施分期与验收

### A：统一底座

完成单模型残留和测试更新、指标目录、证据契约、trace、健康状态及完整真实业务链路验收。保留现有存储和服务边界。

验收：同一范围下页面和工具结果一致；无旧模型调用；队列到持久化链路成功；错误可定位到数据、队列、模型或存储。

### B：自主研究

接入漏斗、路径、交易链、人群、活动、成本质量工具；实现工具发现、研究状态、假设和反证、暂停/恢复、证据定位。

验收：能复现一次跨三个以上业务模块的调查；每个数值可追溯；越界工具请求被拒绝；重复查询和数据不足有停止条件。

### C：业务记忆与闭环

接业务背景检索、人工/AI历史、建议转运营任务、复盘指标注册表、经验状态和评估集。

验收：能解释为何复用或拒绝旧经验；行动效果不能被采纳按钮直接标记有效；失败经验可检索且不会当作成功策略。

### D：预算内持续探索与策略改进

用户开启后按数据水位和事件触发研究；维护问题队列、影子评估、策略版本和回滚。仅重要新发现或需行动时提醒。

验收：相同水位不重复研究；预算和停止开关有效；更新必须通过固定评估；退化可回滚；完整调查可重放。
