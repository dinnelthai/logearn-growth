# 现有功能整理与 KOL CRM 第一版方案

日期：2026-10-14。依据当前工作区代码与文档整理；代码存在不代表线上部署已验收。本文保留完整功能方案；第一版已实现范围与限制见 [KOL_CRM.md](../KOL_CRM.md)。

## 一、目前已有功能

| 功能 | 当前用途 | CRM 可复用能力 |
|---|---|---|
| 首页 / 北极星 | 每日有效分析用户、趋势与使用概况 | KOL 使用趋势 |
| 漏斗 / 留存 | 行为转化、首次观测后的回访 | KOL 带来用户的使用质量 |
| 用户分群 | 账号、行为、绑定、资产、积分、Credits 筛选 | 查找并关联 KOL 账号、查看用户画像 |
| 推荐增长 | 一级绑定关系、推荐人贡献、下级使用与传播 | KOL 的直接邀请用户及贡献 |
| 渠道分析 | 首次来源与来源用户的行为表现 | 补充获客来源；当前来源不能自动等价为某个 KOL |
| 行为路径 / 页面访问诊断 | 会话行为、访问页面、入口与卡点 | 查看 KOL 及其用户的使用过程 |
| 交易监控 | 提交、成功/失败终态、异常下钻 | 查看交易问题 |
| 交易量数据 | trading_transaction 的 USD 成交额聚合 | 需要增加可靠账号映射后的 KOL / 人群聚合 |
| 活动监控 | 固定用户名单、观察窗口、分析完成追踪 | KOL 合作活动效果 |
| 我的监控 / 分析任务 / 用户群组 | 保存关注对象、人群与运营结论 | 复用分析入口与名单下钻 |

现有后台以增长分析为主，尚缺 KOL 档案、合作阶段、跟进记录，以及按 KOL 汇总的持续业务表现。生命周期主要用于分析，不作为已上线消息发送能力。

## 二、第一版业务闭环

录入 KOL → 关联 LogEarn 账号 → 记录合作和跟进 → 查看本人使用与交易 → 查看直接邀请用户贡献 → 决定继续跟进或合作。

KOL CRM 放入一级入口「运营工作台」，与活动监控共用工作台；采用列表页和详情页，不额外增加顶层导航。完整导航整合见第六节。

### KOL 录入

- 必填：名称、平台、主页链接、负责人、合作阶段。
- 可选：联系方式、地区 / 语言、标签、备注、下次跟进时间。
- 数据关联：LogEarn 账号 ID、经校验的推荐关系 / 邀请链接；没有账号也可以先录入。
- 合作阶段：待联系、已联系、沟通中、试用中、合作中、暂停、已结束。
- 合作信息：开始 / 结束时间、合作形式；费用和结算可后续补充。
- 跟进记录：时间、记录人、沟通内容、下一步；保留修改历史。

主页链接可提示重复；一个账号重复关联多个 KOL 时必须提示并处理。名称、社交昵称、钱包地址不能靠相似度自动关联账号。账号未关联显示「待关联」，不能显示为零交易或零使用。

### 列表页

支持搜索、负责人 / 阶段 / 平台筛选，7 / 28 / 90 天及自定义统计期，默认 28 天。允许按成交额、有效分析次数、最近使用或下次跟进排序。

| KOL | 阶段 | 负责人 | 本人成交额 USD | 本人有效分析次数 | 最近分析 | 直接邀请人数 | 邀请用户成交额 USD | 下次跟进 |
|---|---|---|---|---|---|---|---|---|
| 示例 KOL | 试用中 | 运营 A | 待接入 | 待接入 | 待接入 | 待接入 | 待接入 | 2026-10-20 |

表格示例没有真实业务数据。每个指标显示统计范围、数据截止时间和覆盖状态。

### 详情页

1. 档案与合作：账号关联、平台、阶段、负责人、合作信息、跟进时间线。
2. 本人表现：成交额、交易笔数、有效分析次数、分析活跃天数、最近分析时间、每日趋势。
3. 邀请贡献：累计直接邀请人数、本期新绑定人数、本期分析用户数 / 次数、交易用户数 / 成交额、可下钻用户列表。
4. 操作：新增跟进、修改阶段、进入用户画像 / 交易明细 / 行为分析。

本人表现与邀请贡献分别展示。邀请用户的交易量不能写成本人的交易量。

## 三、核心统计口径

### 交易量

- 第一版建议默认展示「成交额 USD」，同时提供交易笔数。
- 当前 tradeVolume.js 已依据业务确认将 trading_transaction.trade_value 作为 USD 金额，以 chain + transaction_hash 去重并使用绝对额聚合；当前覆盖标记为 partial。
- 现有聚合按源 user_id 计算，CRM 必须先核验与 account_v2 的身份映射，不能直接假设源 user_id 就是 CRM 账号 ID。
- 交易事实范围、买卖 / 路由多记录、自动策略覆盖、冲突及缺金额需要确认；不拿提交次数、成功事件数量或手续费代替成交额。
- 金额缺失单列笔数与覆盖提示；若只能聚合部分金额，明确标注「已知成交额」。

### 有效分析次数

业务目标为「用户主动发起的筹码分析或下钻成功完成」。点击、失败、后台抓取与轮询不计，成功缓存命中可计；空结果是否算有效仍需确认，确认前单列。

当前共享集合为 chip_analysis_viewed / chip_analysis_drilldown，北极星主要统计每日去重用户。现有事件条数不能直接宣称为准确的业务分析次数：展示可能重复，展示与下钻可能关联同一次操作，当前完成与曝光语义也有待统一。

- CRM 同时展示「有效分析次数」「分析活跃天数」「最近分析时间」。
- 建议新增稳定 analysis_action_id，代表一次用户主动操作；重试复用 ID，成功完成以 ID 去重，曝光不另增一次。
- 用户主动发起新的下钻算新操作；同一次操作的展示与完成只计一次。
- 事件补充账号、Token、链、操作类型、完成状态、完成时间，以及 request/result 关联。
- 历史数据没有操作 ID 时，展示「已观测分析事件数」，按稳定 event_id 去重并标注口径；不能把它与新口径拼接成精确累计次数。
- Credits 累计已用不是本期有效分析次数。

### KOL 带来的用户

- 第一版使用后端确认的一级推荐绑定关系，不凭 UTM、相邻访问或社交昵称猜测。
- 本期新增人数按 bound_at 统计；本期贡献使用截至期末已绑定的直接邀请用户，行为必须发生在绑定之后且落在统计期内。
- 不纳入二三级用户，不把 KOL 本人重复纳入邀请贡献。
- 合作效果另设合作窗口，统计合作窗口内且绑定后的行为，与普通期间贡献分开解释。
- 推荐绑定贡献与营销触点归因含义不同。精细链接 / UTM 归因作为后续扩展，不默认覆盖正式推荐关系。

所有期间使用 UTC+7 自然日与 [start,end)；未知为 null，已确认无记录才为 0。历史覆盖不足不能解释为从未使用或已经流失。

## 四、实现建议

CRM 档案、跟进及账号关联写入后台自己的数据库；业务事件、账号、推荐和交易事实继续只读查询现有数据源。复用鉴权、分析作业、快照、分页下钻和手动刷新。按现有 owner_id 隔离，团队共享权限单独设计后再开放。

建议新增 kol_profiles、kol_account_links、kol_followups；多次合作时再拆 kol_cooperations。账号关联记录有效期、操作者及证据，修改后保留历史。

建议接口：

- GET / POST /api/crm/kols：列表、录入。
- GET / PATCH /api/crm/kols/:id：档案、阶段与关联配置。
- GET / POST /api/crm/kols/:id/followups：跟进记录。
- POST /api/metrics/kol-crm：按 KOL 与时间范围生成表现汇总，复用现有 202 作业机制。
- 交易、分析、直接邀请用户下钻复用同一分析作业快照，汇总与名单口径一致。

## 五、交付顺序与验收

第一阶段：导航整合、保留现有活动监控完整能力；新增 KOL 档案录入、账号关联、阶段 / 负责人、跟进记录、本人交易额与已观测分析事件数；支持 KOL 与活动关联、互相进入详情。

第二阶段：正式有效分析次数口径、直接邀请用户表现、每日趋势与下钻、合作窗口。

后续：费用、ROI、佣金 / 结算、多链接精细归因、团队协作。数据和费用未完整接入前不展示推算 ROI。

验收重点：未关联 / 缺数据 / 确认零值区分；关联账号冲突检查；重复事件与交易去重；同一次分析不重复计数；绑定前行为排除；期间与累计分开；汇总、趋势、名单一致；权限隔离；修改档案不丢跟进记录。

## 六、导航与活动监控整合（2026-10-14 补充）

### 顶层收敛到四个入口

| 一级入口 | 内容 | 原入口去向 |
|---|---|---|
| 总览 | 平台有效分析、交易量、增长转化、D1/D7、趋势 | 首页、北极星、我的监控整合；详细指标按区块展开 |
| 运营工作台 | 默认待办摘要，下方切换 KOL / 活动列表 | KOL CRM、活动监控；分析任务作为运营记录与下一步入口 |
| 用户 | 用户列表、筛选、用户群组、画像 | 用户分群、保存群组；资产 / 积分 / Credits 放画像和高级筛选 |
| 数据分析 | 二级菜单：获客、转化、行为、留存、交易 | 渠道与推荐合并到获客；漏斗到转化；路径与页面诊断到行为；交易成功率与异常到交易 |

「价值闭环」已有且可用的指标按内容归入总览 / 用户 / 交易；未接入内容不占顶层入口。交易问题在总览提供摘要卡片和直达入口，完整监控在数据分析的交易页面保留。

「我的监控」当前实际是平台级转化 / 留存监控，归入总览；不能误当个人收藏或 KOL 人群监控。总览保持平台分母，不跟随运营中的活动 / KOL 人群变化。

通过二级菜单与详情页逐步展开功能，不将所有原有标签再复制成一排常驻二级标签。保留既有页面查询和下钻能力，先整合导航与入口，再逐步整合重复内容。

### 运营工作台布局

- 顶部：「新增 KOL」「创建活动」两个动作。
- 摘要：待跟进 KOL、进行中活动、已到截止待结算活动；点击进入对应筛选列表。不增加独立待办标签或自动消息发送能力。
- 下方两个切换项：「KOL」「活动」。负责人、状态、时间等放筛选区。
- KOL 详情采用档案摘要、本人 / 邀请贡献、关联活动、跟进记录的纵向区块。
- 活动详情采用活动摘要、指标与趋势、参与者名单、记录的纵向区块；完整行为时间线继续侧栏打开。

### 活动监控必须保留

保留粘贴账号 / 单列 CSV 导入、最多 5000 人、账号校验、固定名单、固定分母、创建时间为开始时间、UTC+7 截止时间、每日新增 / 累计分析用户、状态筛选、搜索分页、活动期间时间线、截止后至少 24 小时手动结算和结果冻结。

活动可关联零个、一个或多个 KOL；独立活动无需先创建 KOL。KOL 可关联多个活动。关联只表示参与合作，不自动证明该活动所有用户都由这个 KOL 带来。

创建流程：填写活动名称 / 负责人 / 截止时间 → 可选关联 KOL → 导入并校验名单 → 展示有效人数与排除原因 → 创建并冻结名单。创建前可以从已有用户群组预填名单；从 KOL 的直接邀请用户预填时，需明确推荐关系口径并确认名单。创建后的新邀请者不自动加入该活动。

现有活动开始时间保持创建时刻；若以后需要计划开始或回溯活动，单独升级时间和基线逻辑，不能只加一个日期输入框。

### 活动指标分两层展示

| 指标区块 | 内容 | 分母 / 统计对象 |
|---|---|---|
| 激活效果（保留现有） | 待首次分析人数、新完成分析人数、完成率、每日新增 | 创建时尚未观测分析的固定参与者；历史待核对保持现有规则 |
| 使用与交易（新增） | 分析人数、分析次数、分析活跃天数、交易人数、交易笔数、成交额 USD | 全部固定有效参与者在活动窗口内的行为，含开始前已分析者 |

第一阶段先保留现有激活区块；新增使用 / 交易区块需复用 CRM 指标口径，未完成接入时显示待接入，不伪装为现有能力。次数沿用前述新旧口径区分。

同一用户可以参加多个活动，各活动内去重；跨活动汇总必须重新按用户 / 操作 / 交易去重，不直接把活动卡片相加。多 KOL 活动默认只展示活动整体效果；若需要逐 KOL 分摊，必须另有明确成员归属，不平均分摊。

活动关联 KOL 后，KOL 详情可查看活动结果，但不将参与者自动加入该 KOL 的直接邀请贡献。活动达到截止后只统计窗口内行为，结算冻结新增指标与原激活指标应采用同一结果版本。

### 最常用的运营路径

1. 录入 KOL，关联账号，看本人使用与交易并记录下一步。
2. 在 KOL 详情创建关联活动，导入或预填并确认参与者名单。
3. 在活动里看谁已完成、谁活跃但未分析、谁在交易，打开用户画像或行为时间线。
4. 活动截止并完成结算后，从 KOL 详情回看每次合作效果，更新合作阶段与跟进记录。

验收增加：原活动可继续访问、导入与结算不回归；原导航页面均有明确新入口；KOL / 活动关联不修改名单；活动和平台分母不混用；新旧查询切换不接受迟到响应。

落地进度：已完成四个顶层入口和按当前入口显示的二级导航，原页面模式、查询及下钻继续复用。首页 / 北极星 / 我的监控分别归入总览下的平台概况 / 有效分析 / 增长转化；活动监控归入运营工作台；用户分群归入用户；渠道、推荐、漏斗、路径、留存、交易归入数据分析。切回一级入口会记住本次会话最后打开的子页面，载入保存配置同步导航高亮。

运营工作台现提供 KOL CRM 与活动监控。已实现 KOL 档案、账号校验、跟进、本人 / 一级邀请用户指标和活动双向关联。工作台统一待办摘要、活动新增使用 / 交易指标及精准完成操作次数仍待实现；CRM 内提供跟进到期数量。原分析任务在当前代码中已停用，这次不重新开放；平台指标的内容合并也尚未完成。
