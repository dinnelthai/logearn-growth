# OPS 运营工具：单个与批量操作

2026-10-17，Asia/Bangkok。需求来源为用户提供的运营接口说明。未复制其中的任何 Token、密码或消息示例，也未使用它们访问线上接口。

## 页面与操作流程

入口：运营工作台 → OPS 工具。

1. 配置当前管理账号的 `logearn_token`，保存后仅展示“已配置”，不回显原文。
2. 选择业务操作与单个/批量方式。需要用户 ID 的操作可直接填写 ID，或选择“地址（先反查用户 ID）”；登录和平台钱包均复用现有唯一身份解析。VIP/优惠券需使用对应 provider 的登录身份，不能把平台钱包直接当登录身份。
3. 单个填写表单；批量最多100条，支持逐行目标、带字段名表头的 CSV、JSON Lines 及文件导入。CSV/JSONL 每行可以覆盖公共参数。若逐行参数已提供，公共参数可以留空，由后端逐行验证。
4. 生成预览：展示固定后的实际请求参数、人数、去重数及任务 ID。任意行无效、地址未匹配或歧义，整批不进入执行预览。相同目标相同参数去重；同一目标参数不同则报错，不任意选择。
5. 核对预览后点击“确认以上操作并执行”。预览15分钟有效；执行请求不接受新的参数覆盖。
6. 查看逐条返回结果；可停止尚未发送的项。当前已发送请求继续等待结果，停止不意味着撤销已提交的业务操作。

页面附销售内部/外部 BI 链接。没有重建 BI 看板，也未读取其数据。

## Token 保存

- 后端按管理账号 owner 隔离，AES-256-GCM 加密保存到 SQLite 的 `ops_credentials`；owner 作为附加认证数据，防止直接交换不同账号的密文。
- 优先读取服务端 `OPS_TOKEN_ENCRYPTION_KEY`，格式为64位十六进制。未配置时，首次保存 Token 会在 SQLite 数据库所在目录生成 `ops-token.key`，权限0600。默认目录为 `backend/data/`，已忽略；文件名也单独加入 Git 忽略规则。
- 数据库与密钥需一起保留/备份；丢失或替换密钥后需重新录入 Token。页面不提供密钥下载，不把 Token 写入 localStorage、审计参数或响应。
- “已配置”只表示已保存，未调用业务写接口验证权限。移除 Token 不删除历史记录；当前有任务运行时不可移除。

## 执行与返回状态

后端固定调用 `https://logearn.com/logearn/` 下的白名单路径，不接受客户端传入任意 URL。Token 仅加入后端请求头。禁止自动跟随重定向；请求超时20秒，响应上限64KB。每账号同时最多一个执行任务，全服务最多两个；批内串行执行。

初版缺少响应样例，统一保持待核实。用户后续提供聊天 [支持 API 请求运营](codex://threads/01a0faa7-a7be-70f1-b1c9-6697ceb56cd3)，本轮从其中的真实命令返回确认以下规则：

- **SKILL 成功**：HTTP成功、数值业务码 `200`、`message="success"`，且返回用户 ID、quotaAmount、余额差与请求完全一致，存在 paymentTxHash。整数使用 BigInt 对账；不接受已损失精度的数值。
- **VIP 成功**：相同成功码与消息，返回有效用户 ID、status=1、有效且尚未到期的 expireTime。新增可选 `expectedUserId`，填写后必须与返回账号一致；仅用于本地核对，不发送给上游。未填写时明确注明尚未核对预期账号，不能声称身份已对账；返回时间不能证明赠送天数增量已独立对账。
- **Token 失效**：即使HTTP200，`code=401,message="TOKEN_INVALID_OR_EXPIRED"`也判失败并停止未发送项。
- **权限不足**：即使HTTP200，`code=500,message="权限不足"`也判失败并停止未发送项。
- **身份未绑定**：SKILL/VIP 的 `code=500,message="地址未绑定，请先绑定钱包"`判当前行失败，不终止其它用户。
- **成功码但对账冲突/缺字段**：保持待核实并停止后续项，不判定未发放，不允许自动重试。
- 其余接口没有足够响应证据，仍保持待核实，不将 SKILL/VIP 规则扩散到优惠券、交易等级或销售接口。超时、断线、未知格式/错误码也不自动重试。

保存脱敏 JSON供核对；Token、密码、API key、私钥字段及当前 Token 字符串被移除。补充 API key 过滤是因为历史 SKILL 响应包含 apikey 字段，不能直接展示该凭据。没有复制历史 Token、用户联系方式、API key 或发放凭据到代码或测试样本。HTTP401/403仍停止后续项。

执行同一个任务 ID 多次不会重复发送。服务重启会把正在发送的行标记“待核实”，未发送行取消，不自动恢复写入。上述机制防止本系统重复提交同一预览，**不代表上游提供幂等保证**；新建预览仍是新的业务操作，未知结果应先去源系统核实。

## 接口与存储

- `GET /api/ops/config`：操作定义及当前账号配置状态。
- `PUT /api/ops/token`、`DELETE /api/ops/token`：保存/移除 Token。
- `POST /api/ops/preview`：`{operation,rows}`，创建冻结的预览。
- `POST /api/ops/batches/:id/execute`：`{confirm:true}`，仅执行已保存参数。
- `POST /api/ops/batches/:id/cancel`：停止未发送项。
- `GET /api/ops/batches`、`GET /api/ops/batches/:id`：当前账号最近任务及逐条结果。

全部入口挂载现有 requireAuth。另新增 `ops_batches`、`ops_batch_rows` 记录任务和行状态；schema.sql 会在正常启动/迁移时创建。实现面向当前单 Node 服务进程；未来多进程部署需增加跨进程执行租约，不能直接共用此内存并发计数。
