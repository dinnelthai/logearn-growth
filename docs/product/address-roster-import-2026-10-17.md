# 地址反查用户 ID 与活动标签

2026-10-17，Asia/Bangkok。

## 使用方式

在活动“名单来源”选择 **登录地址 / 平台地址**，粘贴地址或导入单列 CSV/TXT，点击“识别地址并载入用户 ID”。系统显示地址、对应用户 ID、来源与未匹配/冲突结果；唯一匹配账号去重后进入原用户 ID 名单。再校验名单，保存新活动或更新现有活动标签。

已复用到新建活动、预约名单编辑、追加批次及现有活动“当前活动标签”。识别本身不写标签；原有保存动作和账号归属校验继续生效。编辑地址会清空上次识别的 ID 和校验结果，避免误保存旧名单。

## 身份规则

- 支持 EVM 地址和 Solana Base58 地址格式。EVM 地址统一小写；Solana 地址保留大小写。
- 登录钱包从 `account_identity_v2` 的已验证 metamask/phantom 身份读取；平台钱包从 `wallet_v2` 的 active 钱包读取。
- 地址证据及账号必须在同一快照截止之前创建。重复地址、同账号的多个地址去重；一个地址对应多个不同账号时显示冲突，不任意选择账号。
- 未匹配、格式无效、未验证或失效钱包不直接纳入。不存在根据旧账号同号猜测 account_v2 ID 的回退。
- 每次最多 5,000 个不同地址，输入最多 10,000 条记录和 1MB；候选结果超预算明确失败。SQL 使用参数绑定。

## 接口

`POST /api/activities/resolve-addresses`，需要现有管理账号登录，body 为 `{ "addresses": "每行一个地址" }`。

返回去重 `user_ids`、逐地址 `records`、唯一匹配/未匹配/多账号冲突/重复/格式无效统计和快照时间。接口不创建活动、不写标签、不改固定批次。实际标签写入仍走现有活动创建或标签成员更新接口，保留 owner 和版本检查。

### 默认输入框自动识别地址

用户无需切换名单来源：默认“用户 ID / 地址名单”支持 ID、EVM 地址、Solana 地址混合粘贴或 CSV/TXT 导入。点击“校验名单”时先批量反查地址，再校验最终用户 ID，并展示地址 → 用户 ID / 匹配来源。仅唯一匹配账号可纳入；全部地址未匹配时保留原输入，不允许通过空名单校验。编辑名单会清除已校验状态，过期请求不会覆盖新输入。

### 邮箱与追加（append）

- 默认输入框和独立识别入口支持单个/批量邮箱；按大小写不敏感匹配 `account_identity_v2` 中已验证的 email 身份，使用同一快照约束。多账号冲突不纳入，结果显示“邮箱”来源。
- 默认导入方式为“追加”：CSV/TXT、保存人群、KOL来源、独立邮箱/地址查询均保留现有名单并去重；可选择“替换当前名单”。
- 新增“追加名单”输入框和按钮，允许粘贴 ID、邮箱、钱包地址混合名单，合并后重新校验。合并不超过5000条，邮箱与 EVM 地址忽略大小写去重，Solana 保留大小写。

### 追加成员的最终语义（覆盖此前“追加批次”说明）

追加只向原活动加人，不生成新活动/独立目标。活动人数与效果在同一活动中统一计算，开始时间和目标不改变。已有成员去重，新成员的分析基线按原活动开始时间计算。误建的旧子批次在备份后合并成员到原活动，旧记录保留用于恢复，旧链接定位到原活动。
