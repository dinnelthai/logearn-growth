# X 关键词获客模块

入口：运营工作台 → X 关键词获客。此轮完成本地实现、真实读取与隔离页面验收；未发布到线上服务。

## 可以做什么

- 添加、编辑、启停关键词组，每位运营最多10组；预置4组中英文筹码与钱包研究词。
- 手动采集全部启用组或单组；请求立即返回202，后台处理，页面每4秒刷新运行中任务。
- 自动监听默认暂停，可按15/30/60/120分钟开启；后端需常驻运行。
- 首次查询最近24小时，之后增量查询；Latest排序、Unix时间窗口，保留两分钟重叠并按推文ID去重。
- 每组每轮最多3页，每页最多20条；未完成窗口保留固定起止和分页游标，下轮继续。完成旧窗口后下一轮才追新窗口，因此繁忙关键词可能积压，需收紧关键词或调整轮次。
- 同一运营名下同一作者合并为一位线索，保留相关推文证据、关键词来源及原帖入口。
- 可解释规则评分（不是LLM），显示命中的需求表达和研究主题；宣传、长教程、股票/泛话题降低优先级。评分只能辅助人工判断，不能证明购买意向。
- 按状态、关键词、文本、优先处理、到期跟进筛选；每页30位，当前页CSV导出（处理公式注入）。
- 负责人、下次跟进、备注与跟进记录；版本冲突检查，后台采集不覆盖人工状态。已体验要求填写人工确认依据。
- 通用回复参考和带线索编号的UTM链接；操作员复制后在X人工处理。模块没有发帖或私信接口。

## 凭据、费用和运行

后端环境变量：

```dotenv
TWITTERAPI_IO_API_KEY=<仅在后端填写>
X_ACQUISITION_DAILY_USD=1
```

密钥已放入本地被Git忽略的 `backend/.env`，权限0600；不写入前端、响应、文档或Git。App ID不参与读取鉴权。线上发布时需要在目标服务单独配置密钥；本地环境文件不应上传进源码。

采集预算默认每天$1，按UTC+7自然日重置，全后台共享，防止多运营叠加消耗。每次请求（包括重试）先按20条推文预留300积分，成功校验后改为 `max(15, 返回条数×15)` 积分。无法确认扣费的失败请求保留预留并在界面标记。此处是按文档单价估算，不是供应商账单或账户余额，也不包括从本模块之外发起的调用。

单轮全局只运行一个采集任务；SQLite持久化线索、证据、关键词、跟进、日志和费用估算，沿用Growth现有登录鉴权及运营隔离。运行单个后端调度实例，不要由多个进程同时启动调度；启动恢复会把未完成任务标成中断并保留分页进度。

开发运行沿用项目命令：后端 `npm start`，前端 `npm run dev`。后端启动自动创建模块表和索引，评分版本变更自动重算证据及作者最佳推文，不改变人工跟进状态。

## 本轮真实验证

- 数据源：TwitterAPI.io，真实密钥读取成功；连接探测返回20条，约2.9秒。
- 首轮4组较宽关键词读取240条，228条不同推文、191位作者，12页达到单组轮次上限，状态为部分完成；不是接口失败。
- 首轮估算$0.036，另连接探测约$0.003，合计约$0.039，以实际供应商账单为准。
- 抽查发现教程、推广及泛讨论占比高，因此收紧默认需求词和规则评分，未将191位作者标为已接触或已获客。新关键词窗口与首次测试使用的宽词不同；当前保留旧证据，未来按更新后的关键词采集。
- 真实库跟进记录为0，自动监听暂停。视觉及保存操作在内存副本验收，未发送任何消息或污染真实跟进。
- 后端全量372测试通过，前端272测试通过（4跳过）；评分、分页与异步路由调整后相关8测试再次通过；前端生产构建通过。
- 浏览器验收：线索池、详情、跟进保存、关键词保存、异步采集记录；检查并修复深色主题对比和长推文列表折叠。

聚合验证记录：`output/x-acquisition-2026-10-26/smoke.json`。真实作者与推文只保存在被忽略的本地数据库，聚合文件不含密钥或个人名单。隔离验收服务脚本 `output/x-acquisition-2026-10-26/qa-server.cjs` 只使用内存副本、模拟空采集，不提供生产鉴权或真实发送能力。
