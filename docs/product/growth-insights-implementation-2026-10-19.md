# 增长诊断实施与验收

日期：2026-10-19，Asia/Bangkok。基于当前工作区，保留此前未提交改动；未部署、推送或写入远程业务库。

## 入口与功能

新增「总览 → 增长诊断」，平台概况的「继续排查」也能进入。页面按需加载，使用独立的全平台统计期与来源，明确不继承已圈选人群。支持最近日期或自定义时间，最长31天；后端 API 同时支持固定人群，空名单不扩大为全平台。

变化拆解可以把未回访的账号身份用户生成人群任务，复用现有负责人、处理记录和回看结果流程。任务采用服务端固定名单，创建时再次核对注册账号，来源不完整或存在未匹配账号时拒绝保存。匿名用户保留在分析指标中，不进入这类任务。

## 指标边界

- 北极星继续采用筹码查看/下钻并集，用户去重，不改成新请求成功口径。
- 本期截止取请求截止和数据截至的较小值，上期取紧邻本期、相同时长的窗口。两期可能含进行中的自然日。
- 人数恒等式：本期－上期＝首次观测分析＋重新观测活跃－本期未观测回访。两期持续分析在差分中抵消；各维度分别归组，跨维度不能相加。
- 来源、设备与应用版本是历史分组属性。设备/版本取首次分析相关事件的最早非空观测值，不表示用户当前设备或版本，也不能作为版本故障的因果结论。
- 渠道激活从首次观测时刻起24小时计算；D7/D30从首次观测日计算，须目标UTC+7自然日结束。交易使用首次观测后的168小时成熟窗口；它与自然日D7是不同窗口。
- 渠道交易使用现有已验证身份映射与链/交易哈希事实，未匹配账号不进入交易分母；缺金额和冲突单列，全部金额缺失或没有成熟匹配账号时金额未知。买卖绝对值相加，不是收入。
- 行为对比只使用首次分析起24小时内的早期行为。不同小时观测到分析不等于准确操作次数；两组差异用于提出假设，不证明因果或增量。
- 数据可信度的事件分母已经经过既有去重、身份和时间过滤，不包含过滤前的非法记录。账号关联率不等于注册表匹配率；最早观测与最新事件不能证明连续采集完整。
- 请求级诊断覆盖未确认时，比例仅描述已观测样本；历史未观测成功不能判为失败。展示分析请求的实际用户样本量。
- OPS复盘不执行发放。VIP未核对预期账号、失败、未知和未发送行不纳入；整批结束时间是统一观察起点，不冒充逐行发放时间。
- 保存报告包含变化、质量、渠道与行为关联及名单；请求级价值转化和OPS复盘是独立查询，不包含在报告冻结结果中。历史报告不会复活过期作业；可查看冻结名单，继续实时分析需显式重算。关注规则使用当前浏览器设置。

## 实现与预算

- `POST /api/metrics/growth-insights`：复用认证、作业队列、快照、缓存、下钻与固定人群机制。紧凑用户事实最多50000人/32MB，质量版本分组最多2000组，超出报错而非截断。
- 渠道交易最多5000个账号、150000条记录/32MB。交易源失败不会阻断基础增长诊断；对应指标保留未知。
- `POST /api/metrics/value-diagnostics`：独立读取页面、点击、请求及必要诊断事件的完整已观测相关历史，保留最早任意事件时间用于用户阶段。复用现有请求与价值计算，不读取无关的页面停留检查点、策略等完整路径载荷。
- 价值诊断全平台最长7天，固定人群沿用既有最长31天约束；保留150000事件/48MB查询预算和既有作业资源限制。
- `GET /api/ops/batches/:id/effect`：先按owner核对批次，读取经核对的成功行，复用业务使用/交易事实；每个前后窗口都返回来源错误，不补零。
- `GET/POST /api/growth-reports`、`GET /api/growth-reports/:id`：当前管理账号隔离，保存可信服务端作业结果；SQLite新增 `growth_analysis_reports`。最近列表显示30份，不代表只保留30份。
- 运营任务继续复用原接口，新增接受增长诊断作业的未回访账号名单，不接受客户端覆盖用户。
