# 留存曲线实现与验收（2026-10-16）

实现前检查点：`2f2dc2c`，包含地址备注、VIP权益、转化任务等已有改动。留存功能在此提交之后实施。

## 页面与运营流程

留存页提供日批次、周批次、所选期间总批次；支持 D0–D7、D0–D14、D0–D30，以及指定日留存、连续留存。默认按首次有效分析周分组，最多比较四个批次。上方显示固定入组人数与关键观察日，中部曲线，下方为观察日名单与批次明细。

曲线点、明细及名单共用服务端快照。名单分为完整观察日已回访、完整观察日未观测回访、观察未结束／数据待确认，三者互斥。可搜索用户或来源，再使用搜索匹配的全部分页用户继续进入分群、漏斗等模块，并沿用现有运营任务流程。未观测回访不自动认定为流失，不自动创建召回任务。

## 统计定义

- 用户按身份去重；有效分析沿用现有筹码峰事件归并口径。
- 入组依据首次已观测的指定行为，入组时间为开始含、截止不含。首次事实在所选周期之前的用户不重复入组。
- UTC+7 自然日：首次行为所在日为 D0，第 n 个自然日为 Dn，不采用滚动24小时。
- 指定日留存要求 Dn 至少一次回访，可上下波动；连续留存要求 D1 至 Dn 每天都有回访。
- D0 为入组基准，不声称用户已发生另一种指定回访行为。
- 同一快照内各批次固定用户和分母；只在全部入组用户的对应观察日完整结束后绘制正式点。未成熟点留空，不补零、不平滑、不跨缺口连线。
- 日／周入组窗口未结束时标记“入组中”，不绘制正式点；部分周只包含所选入组日期内的人。
- 入组结束日期仅限制首次行为，回访可以发生在该日期之后。回访事实受当前快照截止时刻限制。
- 日期成熟不代表采集完整。历史覆盖未确认时标注“已观测留存”；不把未知数据解释为完整零值。不提供缺乏历史依据的VIP历史留存比较。

## 实现边界

Hologres和SQLite共用留存计算与惰性名单解析，紧凑保存用户、D0及回访日位图。观察长度仅允许7、14、30天；候选截断直接报错，不显示部分样本为完整结果。新缓存按账号隔离；过期缓存要求重新运行，未知名单键返回错误。搜索来源后的跨模块人群物化沿用同一名单。

本地JSON模式沿用同一页面、分组与图表模型，并分别处理指定日与连续留存的数据覆盖。修复了自定义入组起始时间位于日中时遗漏当天用户的问题。异步旧响应不会覆盖新配置或已卸载页面。
