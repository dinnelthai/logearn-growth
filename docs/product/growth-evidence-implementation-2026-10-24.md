# Growth 首批增长能力实施 · 2026-10-24

## 已实现与入口

1. 首页北极星下方和增长诊断各视图增加证据范围：历史覆盖、连续采集水位、观察窗，以及分析行为与请求成功/理解的区别。数据可信度增加诊断去重用户数，按设备、应用版本和诊断版本细分；同一用户可出现在多个组合中，不相加，不假称全站覆盖率。
2. 增长诊断新增“注册与复访”页签：
   - 首次观测后24小时分析，保留旧口径。
   - 账号注册后24小时分析，独立读取account_v2.created_at，含没有行为事件的注册账号；注册事实失败为未知，不能补零。按来源过滤时明确只限该已观测来源。
   - 首次已观测分析后168小时内另一个UTC+7自然日分析。
   - 首次已观测分析后24小时至168小时内再分析。
   - 复访率只使用完整168小时观察批次；待观察与含未成熟的已观测进度单列。区间截止不含，不冒充D7留存。
   - 所有计数关联原作业快照与准确下钻名单，注册但无事件账号也加入作业成员，保存报告时冻结结果。新报告口径版本2，旧报告提示缺少新增能力。
3. 活动详情新增“活动验证：原始分组与实际送达”：
   - 当前固定活动成员可人工分为干预/对照组；每次1—500人，原始分组不可覆盖。预约活动先启动固定名单，结算后不再分组。
   - 保存分组时的活动窗口、成员激活基线、作者和记录时间。活动开始后补记明确计数；原始窗口不会因后续编辑而改写。
   - 追加发送未确认、送达、未送达、跨组接触、说明，记录发生时间、渠道、依据、作者与记录时间。
   - 同一请求标识重复提交不重复记账；不同内容复用标识明确冲突。并发版本检查，原始分组批量操作事务原子性。
   - 按原始分组汇总送达及活动表现；不排除未送达与跨组接触者，不宣称因果增量。送达状态取发生时间最后记录，说明/跨组记录不清除送达状态。
   - owner隔离、名单校验、分页、筛选、错误与重试、切页后的迟到响应保护。归档只读；结算后允许追加核验证据，但不修改原冻结结果。
   - 仅保存记录，不发送消息或发放权益；人工送达依据不冒充通道回执。

## 数据与运行方式

Hologres仅增加只读查询。活动验证存于运营SQLite三张新表：growth_activity_evidence_state、growth_activity_assignments、growth_activity_delivery_evidence。

新增表使用CREATE TABLE IF NOT EXISTS，正常后台启动会执行现有schema初始化，也可使用现有npm run migrate。不要用DB_PATH=:memory:启动正式服务；该配置仅用于本轮测试。没有改写生产业务数据或正式运营记录，也没有重启正在运行的用户服务。

部署/本地启用时需要更新前端构建，并正常重启后台，使新路由和新表生效。本轮未部署。

## 边界

- 仍没有可靠的连续采集水位，也没有扩大产品侧埋点覆盖；当前实现诚实展示未知，不伪造完整性。
- 分析人数仍为筹码查看/下钻代理；没有把“已理解”按钮作为激活事实。
- 账号创建事实不自动排除员工、测试或低质量账号；它代表注册口径，不自动证明有效外部获客。
- 活动分组为人工记录，不进行随机分配；开始后补记不能作为事前随机实验，分组差异不能证明增量。
- 分组表现使用当前活动窗口；后补证据与冻结的业务表现分别保存，不重新解释历史为因果。
- 财务/权益自动事实接入、推广真实浏览器链路验收和自动触达不属于本批交付，未宣称完成。前两者需要权威业务语义或产品侧配合。
