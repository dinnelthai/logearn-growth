# 从产品代码到增长行动的链路 · 2026-10-25

## 两个项目的职责

logearn-web 是产品端：按真实动作采集。Logearn-growth 是 dashboard：读取事实、核对覆盖、解释已观测断点，并把固定人群交给现有运营工作流。本轮不再建设一套采集系统或重复运营后台。

## 产品端已接入

源码追踪发现，当前 checkout 的 logearn-web 已有 Token 点击/详情、筹码查看/下钻及交易提交/WS结果；缺少 dashboard 已支持的 analysis_requested / analysis_request_finished。手动分析沿以下代码进入：

- advance_analysis.vue 的主动范围选择 → detail/analysis/service.ts::fetch_drill_down_data。
- analysis/_partials/_total_result.vue 的刷新 → 同一函数 fresh=true。
- insider_position_checkbox.vue 使用 sniper_drilldown，不进入主动筹码分析尝试口径；策略引擎的后台取数也不计为用户主动操作。

在该函数缓存判断前发起尝试，现有 catch 发明确失败/明确取消，格式化完成后的汇合点发 success/empty；缓存也属于一次尝试。success 表示本次分析数据准备完成，不直接替换原筹码查看/下钻北极星。

新增 events/analysisRequests.ts：每次函数调用以本地轻量引用关联 WeakMap，ID、单调时钟耗时、起始 Token/page visit 全在 growth 层管理。并发不覆盖，终态去重，参数相同的明确失败重试才引用旧 request ID；普通刷新不伪造重试。切页后仍完成标 origin_view_state=left，不能因为离开页面就虚构取消。仅明确 AbortError/ERR_CANCELED 标 cancelled。错误只带固定分类或 HTTP 状态，不发送原始响应、error.message、钱包凭证或分析明细。

交易仍使用现有业务提交与 WS status=4 的真实终态。在 growth 自有 TradeAttempt 中保存提交时的访问快照，终态不从当前新页面补关联。通知缺乏权威的客户端尝试ID，沿用原有匹配规则；若多个可匹配提交属于不同访问，则不填访问关联，避免把交易归给错误的访问。源业务 RPC、订单执行和策略引擎没有改变。

dispatcher 默认加入 diagnostics_version=web-core-chain-v1，具体诊断 adapter 的独立版本可覆盖；详情事件的这个标记用于辨认新版链路采集覆盖，不能单独证明连续完整上报。

## Dashboard 中如何做三件事

入口：**数据分析 → 行为路径 → 转化断点、页面访问与请求诊断（按需加载）**。

1. 数据可信：显示新版详情记录覆盖、缺 Token/链/访问关联、缺 session、主动分析缺访问关联及交易缺访问关联。混有未确认新版采集的历史详情时，断点比例显示“采集待核对”，不把缺事件当真实损失。原埋点验收页面仍负责 event_id、collect人工证据及库侧核对。
2. 定位断点：同用户、Token访问ID、Token与链，24小时内串起详情 → 主动分析发起 → 请求成功 → 提交交易 → 至少一笔交易成功。交易终态需有同 trade_attempt_id 的更早提交；后台刷新、错Token、错链、错访问及窗口外结果不拼接。24小时尚未成熟的访问单列。按来源、设备、首次观测时间和产品入口比较，不把首次观测叫新注册。
3. 推动行动：每一步与成熟窗口未观测下一步的人数均绑定当前任务的准确 list_key，可进入名单及时间线。名单选择“用户分群”后，展开“将这批用户加入运营待办”，生成固定人群任务；复用原来的权限、账号校验、5000人上限、条件/快照/基线以及任务后续观察。不自动发送消息或执行触达，也没有为了演示创建真实任务。

事件时间线新增分析尝试ID、Token访问ID、交易尝试/订单ID、耗时和原视图状态，便于核对某个用户的证据。样本契约白名单补充 trade_attempt_id / trade_id（contract v2），不会把旧交易无关联终态伪造成新链路。

## 真实数据暴露的覆盖问题

已有固定窗口（10/18 00:00—10/25 00:00，UTC+7）本地只读核查：1488会话、296用户；详情8614条、8187次可关联详情访问，197位用户；主动分析尝试9次，8次能接到详情；623条交易事件全部缺 Token访问关联。

因此历史链路中的0笔交易关联**不是0笔真实交易，更不是0%真实交易转化**。新页面保留这个缺口，待产品发布、采集落库并形成成熟窗口后再解释新版观察比例。

该次实际256MB分析 worker约3.09秒完成完整诊断，结果约2.71MB，保持4MiB结果预算。此为单次本地样本，不是浏览器P95。新链路按访问索引处理，不为每条详情反复扫描该用户全量历史。
