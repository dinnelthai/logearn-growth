# 推荐与增长循环：功能设计

状态：功能设计，尚未实施页面或接口。日期：2026-10-11（Asia/Bangkok）。

## 1. 页面要回答的问题

1. 推荐关系带来了多少真正使用、交易或具有价值线索的用户？
2. 哪些推荐人值得继续投入，哪些人只带来了大量未观测使用账号？
3. 被邀请用户是否继续推荐，循环在哪一段停下来？
4. 推荐产生了哪些交易和佣金记录，数据能否支持投入产出判断？

主指标采用“有效推荐贡献”，优先关注使用与价值；注册和关系总量作为分母与背景，支持发现低质量推荐。

## 3. 页面结构与交互

### A. 筛选与概览

顶部：近7/14/28/90天、自定义日期，手动刷新、统计截止时间。

常用筛选：推荐人（账号ID/邀请码）、被邀请者质量（全部/有业务信号/价值线索/近期使用/可联系价值）、贡献方式（直接/二三级佣金）。更多筛选：被邀请者首次来源、注册时间、绑定、账号状态、是否继续推荐、关系身份匹配状态。

默认推荐质量统计保留全部有效且可匹配的被邀请账号；重点卡片和推荐人榜单突出有价值的用户。切换到有业务信号池后明确改变分母，避免隐藏低质量推荐。

概览6张卡片，全部可点击下钻：

- 本期新增一级绑定账号：以 invitation_time 入期、账号去重。
- 本期贡献推荐人：对应新增绑定的不同一级推荐人；身份未匹配贡献另列。
- 绑定后观测使用账号：本期绑定人群中，绑定后至统计截止发生有效分析或实际策略启动。
- 绑定后交易记录账号：同一人群在绑定后有交易记录。
- 有价值线索账号：交易/NFT/近期正余额/可用积分任一项；当前画像，可与使用重叠。
- 可联系价值账号：上述价值线索与已验证邮箱/TG交集。

卡片下面补充：新增绑定中“近期注册账号/存量账号/时间异常”的构成，以及近28天未观测使用的价值账号入口。时间异常与身份未匹配有独立提示和名单。

### B. 推荐质量与趋势

左侧：绑定批次的分析、策略、交易记录用户占比柱图，三个指标可重叠；每根柱形下钻对应分子账号。

右侧：价值线索、近期使用、可联系价值的独立条形占比。重叠标签不做饼图。

下方：每日新增绑定账号/贡献推荐人数趋势，日期可点击下钻。提供“绑定批次转化”与“本期行为贡献”两个视图，日期口径不混用：

- 绑定批次：本期绑定的用户之后发生什么，用于推荐质量评价。
- 本期行为贡献：所有当前有效关系用户在本期的行为，用于运营盘点；注明采用当前关系归属，非历史因果归因。

观察窗提供7/28天。默认概览展示已观测人数；成熟批次比率仅在完整覆盖确认后开放。窗口未结束显示待观察，历史缺失显示观察不足，两者分别计数。

### C. 推荐人贡献榜（核心操作区）

默认按“带来有价值线索账号数”降序，可切换绑定后使用人数、交易记录人数、继续推荐人数、总绑定人数。

表格字段：推荐人、已验证联系方式标签、新增直接绑定、绑定后分析、策略、交易记录用户、有价值线索、可联系价值、继续推荐用户、未观测使用、观察状态。

每一列的人数都可打开对应名单；行点击进入推荐人详情。不显示未统一计价的总交易额；身份未匹配推荐人单列，不冒充注册账号。

详情抽屉分3个页签：

1. 被邀请用户：注册/绑定时间、存量或近期注册、分析/策略/交易事实、NFT/余额/积分、联系方式标签、是否继续推荐。
2. 推荐关系：按一级逐层展开，默认展示两层、每层分页；显示关系绑定与改绑记录、身份异常。
3. 交易与佣金：关系贡献与佣金事实分开，逐笔查看来源交易引用、邀请层级、币种、佣金、原始结算状态。

点击被邀请用户可打开现有用户时间线，也可“作为受众分析”跳转用户分群、漏斗或留存；这是分析操作，不自动触达用户。

### D. 增长循环

展示可核查的循环：一级绑定账号 → 绑定后观测使用 → 使用后继续邀请 → 下一代绑定账号。

严格循环视图要求：下一代 invitation_time 晚于中间用户首次绑定后使用，且中间用户自己先被有效绑定；缺顺序事实归入观察不足。另提供“被邀请用户继续推荐”宽口径，明确其不要求先使用。

关键指标：

- 继续推荐人数：本期绑定账号中，随后作为一级推荐人带来至少一位有效匹配账号。
- 继续推荐率：继续推荐人数 / 当前绑定批次账号数；实时观测比例，未成熟需标记。
- 下一代绑定账号数：满足上述顺序的不同下一代账号，按账号去重。
- 循环产出：下一代账号数 / 当前绑定批次账号数；按7/28天窗口分开，显示成熟和观察状态。
- 传播周期：有完整顺序的“首次被绑定到首次下一代绑定”中位天数，同时显示样本数。

图表使用各阶段人数条形及连接箭头；阶段之间未满足子集条件时不画漏斗。递归拓扑采用分页展开，不一次加载全网。图中二三级上级字段仅作关系参考，新增邀请边以 user_id → level1_user_id 构建并校验循环/冲突。

现有“有效推荐系数 K”改称“每位贡献推荐人的使用贡献”：绑定后观测使用账号数 / 本期贡献推荐人数。这是参与者人均产出，不当作全用户病毒传播系数；尚缺完整分享/邀请曝光数据。

### E. 佣金贡献（第二阶段）

默认按币种与链分别显示记录笔数、佣金原币数量、涉及推荐人与被邀请人数、邀请层级分布；不把不同币种相加为收入或成本。

状态映射、精度、计价单位、记录去重和 source_transaction_id 与实际交易的匹配规则确认后，才开放已结算/待结算金额及交易金额统计。本次不同来源交易引用数与记录数相同，不能仅凭字段名确认每行对应唯一实际成交。

历史佣金按记录自身 inviter_user_id/invitation_level 归属，不用当前推荐关系倒推过去归属。投资回报率需额外取得平台净收入和完整奖励成本后计算。配置表可用于规则说明，不能推断用户实际 VIP 权益。

## 4. 统一指标与数据规则

- 直接推荐仅 level1_user_id；二三级贡献另列，不重复加入一级获客人数。
- is_valid=true、非自邀、有一级推荐人、时间有效；涉及账号画像的指标必须匹配 account_id。
- 同一被邀请账号有多条有效关系时，按明确业务规则选择；冲突无法解决则隔离，不随机选一个。
- “本期绑定”和“本期注册”分开。近期注册的窗口默认绑定前24小时内注册，只是描述性分组，不能证明注册来自邀请；窗口可配置并显示。
- “绑定后分析/交易”限定发生时间不早于绑定；历史交易/NFT只能作为当前价值线索，不能声称邀请带来。
- 存量使用账号再次使用不能称为首次激活。首次使用转化需要覆盖充分的历史首次事实。
- 无匹配账号、身份类型未知、缺行为历史、积分/VIP未知各自保持未知。零分母比例显示“—”。
- 推荐人自己的来源与被邀请者来源是不同筛选；默认来源筛选针对被邀请者，说明分母。
- 列表与指标来自同一快照/作业，分页下钻人数必须匹配。事件与产品事实均显示截止；源改绑/删除属于弱一致，无法证明完整历史归因。
- 图表不可用时，明细表与名单按钮仍可使用；切页销毁实例；未应用筛选不被刷新提交。

## 5. 实施顺序与验收

第一阶段：只读接入真实推荐关系，身份质量提示、6张卡片、趋势/质量对比、推荐人榜、用户下钻、继续推荐及下一代贡献。复用现有分群事实和手动刷新，不修改线上推荐关系或奖励规则。

第二阶段：佣金数据关联、状态和币种语义确认后的贡献面板、关系改绑历史；完整覆盖确认后增加成熟7/28天转化。

后续采集：邀请链接ID、真实邀请访问、绑定来源、分享行为；拿到可靠链路后再设计链接排行和分享转化。

验收重点：绑定与注册区分；一级与二三级不重复；存量用户不冒充新获客；使用发生在绑定之后；循环顺序成立；未知不当零；改绑归因提示；下钻人数一致；未匹配推荐人/被邀请者可独立查看；同一筛选快照可重复核查。

### 全体用户推荐参与与循环传播

增加独立的“用户推荐自增长”区域，避免只对已经参与推荐的人计算平均产出。

| 指标 | 分子 / 分母 | 本次累计观察值 |
|---|---|---:|
| 全体账号推荐参与率 | 至少推荐一位匹配账号的注册用户 / 全部注册账号 | 708 / 6,860 = 10.3% |
| 被邀请用户继续推荐率 | 被邀请后继续推荐的用户 / 严格匹配被邀请用户 | 263 / 1,953 = 13.5% |
| 下一代用户人数 | 中间用户先被绑定、随后推荐的不同匹配账号 | 588 |
| 累计传播产出 | 上述下一代用户 / 严格匹配被邀请用户 | 588 / 1,953 = 0.30 |

这些是当前关系累计快照下的观察结果，观察时长不同，不能据此确认稳定增长或标准病毒系数。被邀请时间和下代绑定时间须顺序有效；尚未要求中间用户先使用，严格“使用后传播”视图另外计算。未匹配/ID=0关系不进入上述用户推荐分子。

正式页面同时提供近7/28天与累计，并增加：

- 活跃用户推荐参与率：在冻结基准期活跃的注册用户中，随后观察窗推荐至少一位匹配账号的人数 / 该活跃用户集合。与全体账号参与率分开显示。
- 新注册推荐贡献占比：本期注册且满足有效用户推荐归属规则的账号 / 本期全部注册账号。绑定晚于注册很久者不算本期推荐获客；绑定前24h注册只能算时间邻近线索，归因规则确认后才作为正式获客指标。
- 下一代使用贡献：上述下一代用户中绑定后观测到使用的人数；价值线索与交易用户人数另列。
- 固定窗口再生产系数：冻结同一基准用户批次，统计之后7/28天内带来的不同新注册推荐用户 / 全部基准批次用户；未推荐者保留在分母。使用版再按新用户是否完成有效使用筛选分子。窗口与覆盖不完整时只展示已观测值及观察状态，不宣布达到自增长。
- 连续批次趋势：按周展示参与率、继续推荐率、下一代新注册/使用产出，判断传播是否持续，而非依靠一次累计值。

用户推荐是否属于非付费自然传播，需要官方/员工/运营账号标签、活动与奖励来源、渠道归因进一步确认。当前先称“用户推荐贡献”，不能把没有邀请码的用户全部当自然增长，也不能把有推荐关系的用户全部当无成本增长。
