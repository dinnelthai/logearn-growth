# 地址备注、VIP 权益与转化任务

日期：2026-10-16（UTC+7）。实现基于当前工作区，未部署线上产品。

## 调研结论与范围

- 当前 Hologres information_schema 只读核验：account_v2、wallet_v2、account_identity_v2、nft_owner 可用；未发现会员类型与到期字段。既有 userFactsCte 的 vip_active 为 NULL。
- 相邻产品仓库 logearn-web 的 src/api/config.ts 定义 /logearn/vip/info、/logearn/vip/prices、/logearn/vip/purchase 等；未取得供后台批量读取的授权接口与身份映射契约，不能直接冒用用户凭据。
- nft_owner 只有链、token ID、持有人及时间，没有会员系列与期限规则。NFT 持有数量展示为系统线索，不自动授予会员状态。
- 现有人群任务保存固定成员和基线，但不是单用户可核验目标；新转化任务与原人群任务并存，统一汇入工作台。
- UI 采用项目已有卡片、侧栏、表格和原生日期时间输入。字段有明确标签、成功/失败状态和可修正错误反馈，参考 W3C [表单标签](https://www.w3.org/WAI/tutorials/forms/labels/) 与 [表单通知](https://www.w3.org/WAI/tutorials/forms/notifications/)。

## 入口与布局

运营工作台 → 待办下方「权益与转化工作区」；注册用户统一详情内使用同一组件并固定用户范围。

三个页签：
1. 转化任务：用户、目标、处理状态、目标结果、检查/截止时间、证据、处理与核验入口；下方创建任务和保存复盘。
2. VIP 与 NFT：人工登记的周卡、月卡、NFT，各自独立起止时间、数量、凭证和说明；编辑与作废留痕；从权益设置任务，或跨页勾选用户批量设置任务。
3. 地址备注：链族/地址、别名、备注、关联账号、更新时间和历史。已关联钱包可以直接写备注，未注册地址可作为独立线索保存。

空状态给出下一步；列表50条分页，搜索/权益状态筛选在服务器执行。表单草稿在组件存活期间保留。用户侧栏内多个地址合并到同一个注册账号，任务按用户计数。

## 数据与身份

- 所有运营表存 SQLite，按登录管理账号隔离；负责人/共享、团队指派尚未实施。
- EVM 地址小写归一，Solana 地址保留大小写。关联账号必须从活跃钱包或已验证 MetaMask/Phantom 身份中匹配；运营备注不是身份映射证据。独立线索后续关联也重新核验。
- 地址归属保存为登记时核验关系，不承诺未来钱包归属不变。
- 权益始终标注人工登记，需要来源凭证；不向线上产品写入会员或购买记录。周卡/月卡到期必填；NFT 期限未知显示「期限待确认」，不推断永久权益。
- 周卡剩余2天、月卡/NFT剩余3天进入即将到期；起止为 [starts_at, expires_at)。未生效、已作废、已到期分开。
- 修改采用 expected_updated_at 乐观锁；地址、权益、任务变更保存前后值和处理记录。修改权益不重写既有任务的周期基线。

## 人群筛选

用户页更多筛选新增「人工登记权益」与「登记权益状态」，可组合业务行为筛选。支持周卡、月卡、NFT、生效（含即将到期）、即将到期、已到期、待生效、期限待确认、已作废，以及有效权益近7天未观测分析。

同一条权益必须同时满足类型和状态；不会用已过期周卡加有效月卡错误匹配有效周卡。登记权益也进入业务用户池，但不改写系统 vip_active，不混入自动认定的价值信号。服务端把当前账号权益固定到分析作业，保存动态条件后重算时取最新权益；客户端不能注入其他账号的权益。

## 转化与核验

目标：完成一次有效分析、指定2–28个不同UTC+7业务日分析、有效交易、续费、周卡转月卡、自定义人工目标。

- 创建时固定用户、开始时间、截止（最长366天）和目标相关基线；基线来源失败拒绝创建。续费/升级保存对应权益原始周期。
- 相同用户同类进行中目标拒绝重复；续费/升级同一权益周期已处理后也不重复建，取消后可重新设置。
- 批量最多50人，按用户防重；先准备所有相关基线，再用一个事务保存。有冲突整批回滚。
- 处理状态：待跟进、跟进中、已处理、已取消。完成/取消需处理记录。
- 目标结果独立：尚未核验、观察中、已核验达成、人工确认达成、到期未观测达成、数据待确认。
- 自动行为核验由「核验目标」按钮触发，取 [任务开始, min(截止,数据截至+1)) 的真实事实。交易复用已验证身份与去重事实。不同日分析以UTC+7业务日去重。
- 已核验达成保留证据；查询失败保留原结果；源截至尚未进入任务窗口为数据待确认。未观测达成不宣称确定未使用。
- 续费、升级、人工目标仅允许带凭证人工确认；不会把人工录入权益或新到期时间自动当作购买证据。确认结果明确标注人工来源。
- 目前不是「终身首次分析」目标，也不承诺成熟完整历史。

## 复盘

保存当前账号/指定用户范围内的不可变报告，按目标去重用户，自动核验与人工确认分别统计，保留每项任务的原始窗口、基线和结果。不同目标不能直接相加成为总用户。观察转化率不解释为因果增量。报告最多5000项任务，历史列表显示最近50份。
