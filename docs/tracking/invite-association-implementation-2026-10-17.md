# Dashboard 邀请入口与关系关联

入口：数据分析 → 转化 → 邀请转化，新增「邀请入口与数据库关系关联」区域。

## 已实现

- 加载 page_viewed、first_visit_captured 的历史邀请落地证据，以及 invite_link_visited；只解析本站入口 URL 的 referral 参数，不把 referrer（上一个页面）当作本次邀请入口。
- URL 与关系表 inviter_referral_code 在后端转换为 SHA-256 比较键，任务不保留落地 URL 原文，响应不返回邀请码或比较键。
- 登录前 anonymous_id 与登录后真实 actor user_id 关联，沿用统一身份仅唯一账号映射规则；有明确 invite_flow_id 时优先要求同流程。登录时间必须在访问后的 1/24/72 小时观察窗内。已登录入口允许用自身真实账号确认身份。
- 关系须通过现有双方账号、时间、非自邀、无冲突及无循环校验。只有被邀请账号、邀请码和绑定时间窗口均匹配、唯一候选入口且无已知换绑，才标记「邀请码、身份与关系时间匹配」。绑定可早于客户端登录成功回调。
- 同页面 ID 的重复证据合并；同会话 30 秒内 first_visit_captured 与 page_viewed 的同码证据合并。其余多个候选入口保持歧义，不按最近时间强行分配。
- invitation_relation_change_log 中发现旧邀请人非零且发生变化的用户，保守标记「存在换绑记录，历史归因待核实」。不把当前关系倒填为当时关系，尚不重建完整历史版本。
- 缺码仅可确认身份/时间；已有关系、邀请码不一致、多个入口、换绑、跨身份流程冲突分别展示。访问、登录、关系和分析时间均以 UTC+7 显示；名单可下钻，状态筛选先于记录截断，汇总与名单不截断。
- 原显式事件流程与校验统计独立保留。不把数据库匹配当作邀请码校验结果；历史覆盖未知，不展示完整入口转化率。

## 实数验证

2026-10-17（UTC+7）直接使用数据库取数与正式分析函数，最近 28 天 / 24 小时窗口：62 个可识别入口、14 位身份确认用户、2 位邀请码与关系时间匹配用户、2 位匹配绑定后分析用户。该快照无显式 invite_flow_id 流程。摘要见 output/conversions/invite-association-live-summary.json，计数随数据与快照变化。

## 验证范围

后端测试覆盖匿名登录、账号不匹配、跨会话、多入口、缺码、错码、旧关系、换绑、服务端绑定早于回调、窗口边界、记录截断与过滤、原始 URL 不进入任务。前端测试覆盖独立关联区域、证据文案、时间列与转义。

未修改 logearn-web 或数据库。尚未部署正式环境。历史 URL 缺失或新版已脱敏时不会还原邀请码，仍可展示明确流程身份关联及独立关系事实。
