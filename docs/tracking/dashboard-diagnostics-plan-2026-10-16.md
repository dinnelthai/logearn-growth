对应产品交付：[前端补充事件清单](frontend-diagnostics-events-2026-10-16.md)。事件名为本次拟定契约，需产品落实并验收入库，不代表已有数据。

## 第一批 P0：停留、跳出与分析请求诊断

- [x] 接入 page_engaged：与 page_visit_ended 按身份、page_visit_id 合并，累计可见停留取MAX，不相加；首屏停留现有计算也需读取该证据，避免停留已满10秒但未离开者被标时长未知。
- [x] 首页跳出率：首页严格为主页面 `/`、`/cn`、`/en`（统一末尾斜杠），不能仅按page_name=signals选择；基于产品最新README建议，在同一session_id内按连续30分钟无采集活动分段，分段算法须共用于入口、首屏与跳出，避免分母不一致。变更前验证与既有标签页会话报表的差异，保留历史口径说明。
- [x] 首页有效互动满足任一：page_engaged；第二个不同page_visit_id实际呈现；manual登录成功、筹码曝光/下钻、交易提交、策略启动。历史无page_engaged可用停留MAX>=10000ms作正向证据。会话按入口时间入组，跨期查询保留前后上下文。
- [x] 跳出分母仅含观察已结束且可判定的首页进入会话；没有有效互动、且证据足以证明首页停留不足10秒者才计跳出。30分钟静默仅是观察结束规则，不证明真实关闭；进行中、采集边界/关联缺失/仅有隐藏检查点且可能恢复后丢失等无法判定的会话单列未知。不能将缺快照视作0。展示规则、版本边界、可判定分母和未知数。
- [x] 分析请求面板：发起请求数/用户数、成功有结果、空结果、失败、明确取消、待观察、结果未知；按analysis_request_id统计尝试，不以事件条数作分母。同ID重复终态去重，冲突隔离；终态跨统计期仍归发起批次。
- [x] 分析成功率：成功且有结果请求 / 可确认终态请求（成功、空结果、失败）；明确取消单列排除，待观察和结果未知不入分母。同时展示成功请求/全部发起请求的已观测完成占比，避免少终态时误读。新请求指标先独立展示，不擅自替换既有北极星。
- [x] 分析耗时：成功、空结果、失败分别显示中位/P90及样本数；缓存/新请求分开，使用产品上报的单调时钟duration_ms，不以网络到达时间或跨事件墙钟相减冒充准确耗时。
- [x] 等待中离开：有明确page_left/token_changed/ui_closed取消证据的请求 / 可确定结局的发起请求，名称标“等待中离开（明确取消）”；单纯页面隐藏、缺完成事件不能判离开。结果回来但旧页面已离开、后台仍运行的请求单列“完成时原视图已离开”。不能把上述比例称整体用户流失率。
- [x] 失败原因排行、空结果比例、重试次数及重试后成功率；同一用户主动重试为新request_id，用retry_of_request_id串联，发送重试仍复用event_id。
- [x] 展示请求/页面/Token访问关联覆盖率、终态覆盖率、未知状态、采集版本与样本量；所有名单/请求下钻使用同一查询快照。

## 第二批 P1：入口、首次价值、登录与页面性能

- [x] 入口点击→详情→成功分析：复用ranking_token_clicked/callout_card_clicked/token_detail_viewed，按token_visit_id匹配新增请求结果；缺关联单列，不用时间邻近补ID。
- [x] 卡片曝光→点击：按同page_visit_id与item_exposure_id关联；曝光对象去重口径与点击一致，分别展示曝光用户、点击用户与卡片曝光/点击次数。unknown入口保留，search/trenches按list_type区分，不猜造entry_module。
- [x] 首次观测访问→首次成功分析：用户去重、固定24小时转化窗口（产品如另定需统一修改），显示已转化、未转化、未成熟、未知；耗时仅针对同身份且有效关联样本。无完整历史只称首次观测，不称账号生命周期首次。
- [x] 登录阶段诊断：按钮点击→登录尝试→钱包连接/签名/认证结果；按login_attempt_id关联，manual与auto_restore分开；主动取消与系统失败分开，历史无类型维持未知。移动登录按钮未采集为此前接受范围，不静默扩展覆盖。
- [x] 页面核心内容就绪率/耗时P50/P90、明确加载失败率、未完成覆盖；page_viewed只证明页面已呈现，不证明行情/分析图已就绪。首次文档从NavigationStart、SPA从导航开始、浮窗从打开开始，按load_type分别统计，不能混算。

## 公共展示与验收

维度：入口页、已采集来源、设备/视口、新老（首次观测）用户、app_version、业务chain、page/float；请求额外按analysis_kind、trigger、cache_hit、entry_module/list_type区分。未知独立显示，不用小样本差异断言因果。

首批页面顺序：总体转化与状态 → 耗时分布 → 失败/空结果 → 等待中离开 → 维度对比 → 请求及用户时间线。权限、分页、作业预算和快照沿用现有框架；请求开始与结果必须从同一范围上下文取数。由前端与采集后端逐event_id验收，再与Dashboard结果对账。
