# 设计系统基线与迁移原则

当前入口 `main.js` 按顺序加载 `styles.css`、`polish.css`、`brand-logo.css`、`growth-agent-ui.css` 和 `workspace.css`；另有页面私有样式。现存层叠和覆盖关系须先核查，不能把现有样式视为单一设计系统。

后续迁移按任务书：先建立颜色、空间、字体、边框和布局 token 以及可复用组件 API；用一个真实页面验证后渐进推广。默认暗色，保留真实状态与数据质量语义；未知不可显示为零。页面必须保留现有查询、权限、快照和 AI 成本保护。每个组件应定义状态、键盘/焦点、事件清理和错误处理，不靠全局补丁叠加。

当前并未完成对颜色对比度、主题、组件覆盖与断点的视觉审计；本文件是迁移约束，不是已实现的设计系统。

## 2026-10-28 设计系统第一轮收敛

- 新增 `frontend/src/ui-tokens.css`，由 `main.js` 在 `workspace.css` 前引入。它是桌面暗色工作台颜色、边框、圆角、控制尺寸、空间尺度与侧栏尺寸的统一来源。
- 从 `workspace.css` 原根选择器移除重复的 `--a-bg`、`--a-panel`、`--a-text`、`--a-border` 等声明；侧栏、顶栏、按钮、表单、聚焦轮廓、卡片开始使用语义 Token。此步骤保留现有暗色配色，不更改业务视觉含义。
- `viewStates.js` 继续作为错误、空态、局部旧数据、不可用状态的基础渲染组件。扩展至 `channelsAgg`、`pathsAgg`、`tradeMonitorAgg`、`segmentsAgg`，此前已经接入首页、漏斗、运营待办。
- 所有错误重试必须经过真实用户点击，不在渲染、挂载或状态切换时自动重新发送请求。旧快照展示必须显式标记，不能误报新鲜数据。
- `retentionAgg` 移除围绕公共 `dataTable` 的冗余横向滚动壳，避免嵌套滚动区域。

尚未完成：全量 CSS 旧样式删除、所有组件迁移、页面级视觉检查和设计 Token 的全站覆盖。不得标记设计系统全部完成。
