# 活动监控

入口：独立“活动监控”页签。粘贴用户ID或上传单列CSV（最多5000人），校验后设置UTC+7截止时间。创建时间自动作为开始时间，名单与分母固定。

数据：名单校验匹配远程account_v2，不将“没有事件”等同于未知账号。排除acc_、去重，未匹配和格式无效名单展示但不纳入。活动配置、成员及开始前首次观测分析存于本地SQLite growth_activities / growth_activity_members；事件仍查询Hologres，账号隔离按登录管理账号owner_id控制。

有效分析：共享北极星ANALYSIS_SQL（chip_analysis_viewed OR chip_analysis_drilldown）。创建前已观测分析者不进入首次分析分母。期间首次观测分析发生在[start_at,cutoff_at)才计新完成。查询时用当前快照，开始前迟到分析会标“历史待核对”，不计新完成，固定分母不自动改动。历史覆盖和采集不完整时不能保证用户真正首次使用。

每日新增按UTC+7自然日，累计用户不重复；没有待首次分析用户时转化率为未知。默认名单为“活跃未分析”，可切换待激活、未观测活跃、已完成、开始前已分析、历史待核对；按用户ID搜索并服务端分页。行为侧栏只显示活动期间，可逐页加载事件及清洗后的URL。

截止后新发生的事件不纳入，迟到上报仍可补充。至少等待24小时后可手动“结算并固定结果”，将当时汇总和用户状态冻结；不宣称24小时必然接收全部迟到数据。之后到达事件不再改结果，源数据的修改/删除仍受底层弱一致性限制。

API（全部鉴权并校验owner）：GET/POST /api/activities；POST /validate；GET /:id/metrics（status、q、offset、limit）；GET /:id/timeline（user_id、offset）；POST /:id/settle。

用户分群同时精简：默认筛选、人数摘要、用户列表；运营线索、对比图表与资产/积分/Credits明细默认折叠，图表展开后才初始化。

验证：业务口径与API隔离测试；名单实际远程匹配；真实数据源配合内存数据库创建/指标/时间线烟测（不创建正式活动）；前端构建与原分群状态回归；浏览器校验与页面检查。
