# 效果对比与历史报告

入口：运营工作台 → 效果对比。选择2–8个KOL或活动批次，按当前快照比较使用与交易。KOL对象支持全量搜索和分页，翻页保留已选对象。

## 观察窗

- 统一统计期：7/28/90天或自定义，活动与自己的活动窗口取交集，KOL本人/标签用所选期间，正式邀请仅计绑定后行为。
- 同龄窗口：仅活动，按各自开始时刻起算前1/7/14天（24/168/336小时），不是UTC+7自然日。实际窗口同时受活动截止和数据截至限制；标明已满观察期、尚未满观察期或活动窗口不足，未成熟不能作完整周期结论。
- 不同活动的开始时间跨度导致整体查询超过366天时明确拒绝；单次最多5000个独立相关账号、50000条成员关系，每来源15万条事实，超限不截断。
- 统一统计期可以另输入最多5000位注册用户作比较，自动排除所有所选对象的成员，显示排除人数。不是随机对照，不计算因果增量；合并去重数包括另选人群，各组分别查看。
- 所有组合并按各用户实际窗口、分析事件、链与交易哈希去重，不计活动窗口间的空档。

## 保存和重新计算

运行生成服务器暂存结果，15分钟内填写名称保存。客户端只提交结果标识和名称，不能替换结果或固定成员。临时结果缓存最多50份、32MB，单份4MB；来源失败或无可观测结果不能保存。重复保存同一次结果返回同一报告，不重复创建。

历史报告持久保存在本地后台，按登录账号隔离，列表分页。报告包含固定名单、范围、窗口、口径、结果与数据截至；打开报告不读取远程业务库。更改KOL名单、标签或活动当前状态不改旧报告。

「保留原名单与窗口，用最新数据重算」使用原固定成员和配置重新读取数据。结果需手动保存为新报告，旧报告不覆盖；同龄未成熟窗口可以继续成熟，原目标观察窗不延长。

| 方法 / 路径（前缀 /api/operations） | 用途 |
| --- | --- |
| POST /compare | kind、scope、ids、mode；calendar提供start/end，可选control_user_ids；age提供age_days |
| GET /reports | offset/limit分页列出当前账号的报告 |
| POST /reports | comparison_id、name保存服务器生成的结果 |
| GET /reports/:id | 读取历史配置与结果 |
| POST /reports/:id/rerun | 保留原配置、名单与窗口重新计算，返回新的comparison_id |

已知USD成交额仍有覆盖限制，不等于收入；历史分析沿用观测事件次数。数据源失败保留未知，缺金额和无效交易分别列出。
