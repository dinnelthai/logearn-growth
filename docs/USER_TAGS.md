# 活动与 KOL 用户标签

活动导入且校验通过的成员自动加入当前活动名称标签；开始前已分析的成员也带标签。追加批次共用根活动标签，批次不生成额外标签。截止、结算或归档后标签保留，可单独编辑当前成员。

KOL 关联账号自动具有 KOL 名称标签；KOL 编辑表单可另填标签用户名单，每行一个注册账号 ID，最多5000人，校验匹配后保存。手动名单可重叠；一个用户可有多个活动 / KOL 标签。KOL 的档案自由文本标签与这些用户标签是不同字段。邀请关系不自动等于手动标签名单。

标签使用活动 / KOL 的稳定 ID 关联，显示名称来自原档案；已有记录无需手动补标签，改名自动更新显示。活动当前标签保存在 growth_activity_tags，历史固定名单保存在 growth_activity_members，两者用途分开；关联账号和KOL手动成员继续直接生成KOL标签。删除手动成员或修改关联账号后，相应的自动标签归属随之更新；已经生成的分析作业仍保留当时的标签快照。

当前 Hologres 用户分群增加「活动标签」「KOL 标签」「标签匹配」筛选，支持所选标签交集 / 并集，并与已有受众、来源及其它筛选取交集。选标签默认切换全部注册用户，避免无业务信号的活动成员被默认业务池隐藏。对比维度支持「活动 / KOL 标签」，各组可重叠，每组内去重，组人数不能相加为总人数；同名标签保持不同组。用户列表及下钻显示运营标签。

GET /api/user-tags 返回当前管理账号可见标签及成员数量，不返回完整名单。POST /api/metrics/segments 接收 tag_ids（最多20个）、tag_mode=all|any；服务端校验标签所有者，生成固定标签快照并将所选用户与原受众交集。不存在或越权标签返回404，空交集保持空名单，不能回退全平台。旧快照仅表示当时成员，标签变更后重新运行分析。

目录仅聚合人数；过滤成员仅取所选标签，详情标签仅取当前分析人群。不再按全局累计成员关系数限制普通分群。标签筛选最多50000名独立用户；分析作业仍有独立数据及结果缓存预算，超限明确提示缩小范围。重复标签使用内部字典压缩，API仍返回具名标签。

CRM POST / PATCH 支持 user_ids 字符串或数组；重复用户去重，格式或账号不匹配时拒绝整个名单，不部分保存。编辑不传 user_ids 时保留名单，传空名单时清空手动成员，关联账号仍带 KOL 标签。

验证：标签去重、owner 隔离、并集 / 交集、空受众、改名、重叠分组与下钻、KOL 名单校验 / 清空；真实远程分群作业验证一个用户同时属于活动与 KOL、返回两组各一人。临时验收记录已清理。

漏斗、留存、路径、渠道、推荐和交易页面新增「按活动 / KOL 标签分析」。GET 标签列表后，POST /api/user-tags/audience 将所选标签与已有受众 / 本人保存群组取交集，锁定当前分析时间与远程快照，转为现有通用分析人群；可以跨模块继续分析或清除人群。空交集保留空人群，不扩大到全平台。平台北极星与平台总览仍为平台基准；推荐的全平台累计背景保持原有口径。

## 2026-10-15 · 共用人群入口

用户分群及漏斗、留存、路径、渠道、推荐、交易使用同一个上方「分析人群」入口，支持活动/KOL标签、保存人群和全部注册用户。分群的重复标签筛选器移除；KOL档案tags改名为「KOL分类」，保存的cohort改名为「保存人群」。保存人群支持固定名单与动态条件；动态条件在使用时计算，之后仍固定名单供分析。

更换标签从原始基础人群重新计算，不自动叠加上次标签名单；勾选「与当前完整名单取交集」才累计限制范围，条件来源显示在当前人群描述中。空人群保持空。指定人群开始分析时默认注册用户池，避免没有业务信号的成员被隐藏；之后可在范围内继续筛选。

「保留名单，更新数据」获取新的数据快照，但名单与统计期不变；「重新计算名单」按当前所选标签或保存群组读取最新成员。名单固定时间与数据截至分别显示。用户分群的固定统计期显示真实起止时间，避免被最近7天选项误导。

动态条件人群、活动补录批次、统一用户详情和工作台待办已接入，详见本次实施说明。


## 动态条件人群

分群页「保存筛选条件为动态人群」保存已应用的用户池、来源、业务筛选、相对7/14/28/90天窗口，以及活动/KOL标签的交并集条件。标签的基础范围为空表示全部注册用户；来自其他固定名单的基础范围仍固定。保存时可明确选择动态统计期。

选择动态人群时，从当前远程快照运行已有分群作业，取回完整ID名单后固定；零结果保留为空。重新计算使用最新标签成员和当前快照，保留名单更新数据则不改变成员。动态条件不在浏览器本地降级保存；服务端不会将动态cohort_id当静态空名单解释，须先计算并传固定ID。所有条件和标签仍校验当前管理账号权限。

## 标签与人群版本历史（2026-10-15）

从本版本起，SQLite事务内触发器记录活动/KOL手动名单的实际增删，以及KOL账号关联变动；无变化的KOL档案保存不重写名单。统一标签历史可在保存人群区域查看，用户详情可查看该用户的历史；账号关联动作与手动标签增删分别标注。历史不伪造旧操作时间，固定活动批次不受移除当前标签影响。

动态人群通过所属owner的已完成分群作业保存版本。服务端以持久化规则覆盖请求中的用户池、筛选、基础名单、标签和相对日期；不接受客户端自报的名单或规则快照。每个作业只生成一个版本，记录名单、人数、增减、条件、时间窗与源快照。合法空名单也保存，绝不拓宽成全体用户。静态人群支持显式保存当前版本。版本按20条分页，可查看原条件，并将历史固定名单用于当前数据分析；不把旧快照描述为当前数据。版本列表/读取/保存都校验owner，已删除人群不可访问。

多账号KOL：自动名称标签覆盖全部关联产品账号，并与手动名单去重。任一关联账号的自动标签必须从KOL账号列表解除；解除后，同一账号若仍在手动名单中则保留标签。账号关联增删在同一事务记录，单纯修改备注不会产生虚假的账号解除/添加历史。

## 价值线索卡片（2026-10-16）

用户页运营行为标签的「待激活用户」改为「有价值线索的用户」，复用价值画像定义：注册账号有交易记录、NFT、余额、有效 VIP 或可用 Credits，满足任一项即可；包括已分析与未分析用户。仅注册、联系方式绑定或积分不满足该标签。卡片人数、下钻名单、用户标签与筛选使用相同条件。为兼容已有保存条件，内部筛选键仍保留 unactivated，其语义更新为价值线索。
