# KOL CRM

入口：运营工作台 → KOL CRM，与活动监控共享二级导航。北极星入口恢复为「总览 → 北极星指标」。

## 已实现

- KOL 档案录入 / 编辑：名称、平台、主页、多个注册账号、负责人、合作阶段、联系方式、地区 / 语言、标签、备注、下次跟进时间。
- 按名称 / 平台 / 账号 / 标签搜索，按阶段与负责人筛选，分页；展示总数量与已到期跟进数量。
- 账号校验匹配 account_v2，同一管理账号内禁止将相同注册账号关联到多个 KOL。可以先录入不关联账号，此时业务指标显示待关联。
- 跟进内容、下一步、下次跟进时间；持久保存到后台 SQLite，按登录管理账号 owner_id 隔离。档案修改历史保留，编辑使用 updated_at 检测并发冲突。
- 统一统计期与自定义范围：本人已知成交额 USD、交易笔数、已观测分析事件次数、分析活跃天数及期间最近分析时间。
- 一级邀请贡献：截至期末绑定人数、本期新绑定人数、绑定后且统计期内的分析 / 交易表现；邀请用户分页明细和每日本人表现表。
- 可关联已有活动、取消关联；从 KOL 详情创建活动时预填名称并建立关联。活动可返回关联 KOL，KOL 可进入活动。关联不更改活动名单或分母。
- 原活动导入、固定名单、截止 / 结算逻辑保留；关联可更新，已结算业务结果仍冻结。
- 活动成员和 KOL 关联账号自动成为名称标签用户；KOL 可另录入标签用户名单。用户分群可按活动 / KOL 标签筛选、交集 / 并集及标签分组对比，名单中显示标签。见 [USER_TAGS.md](USER_TAGS.md)。

## 数据口径与边界

分析消费共享 chip_analysis_viewed / chip_analysis_drilldown 并集，以 event_id 去重。页面使用「分析次数（观测）」：历史事件可能把展示与同次操作重复计数，尚不能宣称准确的业务完成操作次数。要升级准确次数需产品上报稳定操作 ID 与完成状态，不能用 Credits 已用额度替代。

交易消费 trading_transaction，USD 口径沿用已确认 trade_value，取绝对值；按链与哈希去重。源业务用户 ID 复用积分 / Credits 的唯一已验证钱包映射：存在旧 user_account 时不能按同数字新账号猜关联。冲突源 ID / 时间 / 金额、缺链 / 哈希排除；缺金额单列，全部金额缺失时金额为 null。未映射交易不计，整体覆盖 partial，不能保证全平台或所有自动策略交易完整。

推荐复用现有推荐增长的最早有效绑定、同时间推荐人冲突、自邀、账号匹配和循环排除规则。本人和邀请用户分别展示；邀请用户行为必须晚于或等于绑定时间且在 [start,end) 中。活动关联不是邀请归因。

CRM 聚合采用同一远程快照截止，UTC+7 日界线，最多366天、5000个相关账号、每来源最多150000条记录；超限明确失败不截断。详情指标接口单次最多50个 KOL。列表按50个档案分页，档案排序仅计算当前页指标；指标排序与行为关注视图先计算全部匹配对象，再排序筛选分页，最多1000个 KOL、50000条成员关系及200万次重叠事实处理。分析、交易、推荐来源独立失败时各自保持未知；排序或筛选所依赖来源失败会明确报错，不能当零值参与排名。远程只读，不写业务数据库。

当前支持推广链接UTM已观测触点归因、人工收益账本ROI、多账号KOL和前期变化率。尚未接入自动触达、自动财务流水、团队共享与KOL独立趋势图；每日表现提供表格。

## API

全部挂在鉴权 /api/crm/kols：

- GET /：列表、筛选、分页和跟进摘要。
- POST /：创建档案。
- GET /:id：档案、跟进、活动和最近50条修改历史。
- PATCH /:id：编辑；必须提供 expected_updated_at。
- POST /ranking：全量指标排序、关注视图及分页，支持 scope、sort、direction、view、q、stage、assignee、start、end；翻页携带 snapshot_id 和 list_version。
- POST /metrics：kol_ids、start、end；返回本人、邀请成员、汇总与每日明细，标明来源错误、快照与覆盖。
- POST /:id/followups：跟进及下一次时间。
- POST /:id/activities：关联现有活动。
- DELETE /:id/activities/:activityId：取消关联，保留活动本身。

POST /api/activities 可选 kol_id，创建时校验归属，并将活动与关联在同一事务写入。

## 验证

后端测试覆盖账号校验、重复关联、跨管理账号隔离、持久跟进、修改历史、并发编辑、活动关联权限与名单不变；指标测试覆盖绑定时间、快照截止、去重、USD 绝对值、未知金额、部分来源失败。另执行真实远程只读查询及浏览器录入 / 编辑 / 跟进 / 活动跳转验收，临时联调记录随后清理。

交易身份与分群、推荐共用唯一已验证钱包规则；存在旧账号时不会回退到同号新账号。直接邀请贡献保留绑定及交易的微秒顺序，同一毫秒内早于绑定的行为不计入。

## 2026-10-15 · 第一批功能整合

详情增加第三种范围「标签用户表现」：当前手动名单与关联账号取并集去重，支持排除本人；未关联本人账号也能展示经过校验的手动名单表现。本人、直接邀请用户、标签用户分别展示；三种范围可能重叠，不能相加。列表增加标签用户/分析人数和已知成交额。

三种范围可带固定名单、统计期与快照进入统一分析入口。直接邀请贡献卡片仍只计绑定后的行为；进入通用分析的固定邀请名单后，通用指标展示所选期间全部行为，页面说明该区别。

列表请求 include_details=false，仅返回汇总，避免重叠名单大量传输；详情返回用户与每日数据。API的 available 表示至少一种范围可用，own_available 表示本人可用；own/invited/tagged/tagged_excluding_own 各自可以为 null。查询错误仍保留未知，账号数据源失败不生成零人数。

## 2026-10-15 · 全量排行与合作批次

列表支持本人、有效直接邀请、KOL标签用户三种范围；按分析人数、观测次数、分析人日、覆盖率、交易笔数、已知成交额和最近分析全量排序。关注视图包含到期待跟进、有分析、未观测分析、有交易、分析未交易。最后一项表示该KOL范围有分析且没有交易，并非逐用户转化漏斗。未关联本人账号时本人/邀请数据未知，标签手动名单仍可使用。

翻页固定业务快照、统计期和档案版本；档案或名单变化后返回409并要求刷新。未知指标始终排在最后。不同KOL可能覆盖同一用户，排行各行不能相加。

每个KOL可建立多个合作批次，分别记录周期、目标、交付、负责人、关联活动、人工成本和复盘。详情位于KOL档案内，不增加导航入口。完成时冻结当前复盘，重新打开修改后再次完成生成新版本，旧版保留。具体账本口径、状态和API见 [KOL_COLLABORATIONS.md](KOL_COLLABORATIONS.md)。

## 趋势与关注阈值（2026-10-15）

列表增加相邻前一期分析次数变化率；前一期使用相同长度窗口、同一源快照与当前所选用户范围。上期零值或查询失败时变化率未知。关注视图新增分析下降、低使用、高成交额，默认阈值为下降30%、分析次数少于3、已知成交额至少1000 USD；可以调整。业务关注仍对全部匹配对象计算后分页，缺少必要数据时拒绝据此筛选。手动关注视图不发送通知，成交额不代表收入。

## 一个KOL关联多个产品账号（2026-10-15）

录入/编辑页支持一次填写最多20个注册账号ID，换行或逗号分隔，自动去重；可逐步补充，也可清空全部关联。每个ID查询真实account_v2验证。同一管理账号内，一个产品账号只能归属一个KOL；并发保存会在远程校验后重新检查冲突。不同管理账号的数据仍隔离。

- 本人指标合并全部关联账号，保留逐账号使用/交易明细；分析活跃人日为各账号活跃天数相加，不把多个产品账号冒充一个注册用户。
- 邀请贡献合并全部账号的有效一级邀请，按受邀账号去重，排除KOL自己关联的全部账号，继续遵守绑定时间/微秒边界。
- 标签名单为手动成员与全部关联账号的并集；「排除本人」排除全部关联账号。解除账号关联只移除自动标签来源，手动录入的同账号标签保留；关联账号不能通过单用户移除标签接口解除。
- 列表/排行榜可搜索任意关联账号；三种统计范围、趋势、效果对比、活动导入和从KOL新建活动全部使用相同账号集合。既有活动固定名单与历史复盘不会随账号变更重写。
- 账号数据不完整时保留未知或未匹配提示，不把缺失账号算作零使用。

POST/PATCH档案的规范字段为account_ids（字符串数组，也接受粘贴文本）；PATCH传入时整体替换关联集合，不传则保留。GET列表/详情/排行返回account_ids。account_id保留为首个账号的兼容字段；旧单账号客户可以继续创建/编辑单账号档案，但不能用该字段清空或替换已有多账号档案，需使用account_ids，防止误丢其他关联。

新增crm_kol_accounts保存完整关联及顺序，并设置owner/account唯一约束与KOL/owner复合外键。启动和migrate命令幂等迁移旧单账号，旧字段同步首个账号，解除后重启不会重新添加。账号增删和档案前后值保留审计。
