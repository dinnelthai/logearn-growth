# KOL CRM

入口：运营工作台 → KOL CRM，与活动监控共享二级导航。北极星入口恢复为「总览 → 北极星指标」。

## 已实现

- KOL 档案录入 / 编辑：名称、平台、主页、注册账号、负责人、合作阶段、联系方式、地区 / 语言、标签、备注、下次跟进时间。
- 按名称 / 平台 / 账号 / 标签搜索，按阶段与负责人筛选，分页；展示总数量与已到期跟进数量。
- 账号校验匹配 account_v2，同一管理账号内禁止将相同注册账号关联到多个 KOL。可以先录入不关联账号，此时业务指标显示待关联。
- 跟进内容、下一步、下次跟进时间；持久保存到后台 SQLite，按登录管理账号 owner_id 隔离。档案修改历史保留，编辑使用 updated_at 检测并发冲突。
- 7 / 28 / 90 天统计：本人已知成交额 USD、交易笔数、已观测分析事件次数、分析活跃天数及期间最近分析时间。
- 一级邀请贡献：截至期末绑定人数、本期新绑定人数、绑定后且统计期内的分析 / 交易表现；邀请用户分页明细和每日本人表现表。
- 可关联已有活动、取消关联；从 KOL 详情创建活动时预填名称并建立关联。活动可返回关联 KOL，KOL 可进入活动。关联不更改活动名单或分母。
- 原活动导入、固定名单、截止 / 结算逻辑保留；关联可更新，已结算业务结果仍冻结。
- 活动成员和 KOL 关联账号自动成为名称标签用户；KOL 可另录入标签用户名单。用户分群可按活动 / KOL 标签筛选、交集 / 并集及标签分组对比，名单中显示标签。见 [USER_TAGS.md](USER_TAGS.md)。

## 数据口径与边界

分析消费共享 chip_analysis_viewed / chip_analysis_drilldown 并集，以 event_id 去重。页面使用「分析次数（观测）」：历史事件可能把展示与同次操作重复计数，尚不能宣称准确的业务完成操作次数。要升级准确次数需产品上报稳定操作 ID 与完成状态，不能用 Credits 已用额度替代。

交易消费 trading_transaction，USD 口径沿用已确认 trade_value，取绝对值；按链与哈希去重。源业务用户 ID 复用积分 / Credits 的唯一已验证钱包映射：存在旧 user_account 时不能按同数字新账号猜关联。冲突源 ID / 时间 / 金额、缺链 / 哈希排除；缺金额单列，全部金额缺失时金额为 null。未映射交易不计，整体覆盖 partial，不能保证全平台或所有自动策略交易完整。

推荐复用现有推荐增长的最早有效绑定、同时间推荐人冲突、自邀、账号匹配和循环排除规则。本人和邀请用户分别展示；邀请用户行为必须晚于或等于绑定时间且在 [start,end) 中。活动关联不是邀请归因。

CRM 聚合采用同一远程快照截止，UTC+7 日界线，最多366天、50个 KOL、5000个相关账号、每来源最多150000条记录；超限明确失败不截断。分析、交易、推荐来源独立失败时各自保持未知，不当零值；成功来源可以继续显示。远程只读，不写业务数据库。列表按50个档案分页，每页指标只查询对应账号。

尚未实现：营销链接 / UTM 精细归因、自动触达、费用与 ROI、团队共享、多账号 KOL、指标排序、图表趋势、活动新增交易 / 使用汇总。当前每日本人表现提供表格。

## API

全部挂在鉴权 /api/crm/kols：

- GET /：列表、筛选、分页和跟进摘要。
- POST /：创建档案。
- GET /:id：档案、跟进、活动和最近50条修改历史。
- PATCH /:id：编辑；必须提供 expected_updated_at。
- POST /metrics：kol_ids、start、end；返回本人、邀请成员、汇总与每日明细，标明来源错误、快照与覆盖。
- POST /:id/followups：跟进及下一次时间。
- POST /:id/activities：关联现有活动。
- DELETE /:id/activities/:activityId：取消关联，保留活动本身。

POST /api/activities 可选 kol_id，创建时校验归属，并将活动与关联在同一事务写入。

## 验证

后端测试覆盖账号校验、重复关联、跨管理账号隔离、持久跟进、修改历史、并发编辑、活动关联权限与名单不变；指标测试覆盖绑定时间、快照截止、去重、USD 绝对值、未知金额、部分来源失败。另执行真实远程只读查询及浏览器录入 / 编辑 / 跟进 / 活动跳转验收，临时联调记录随后清理。

交易身份与分群、推荐共用唯一已验证钱包规则；存在旧账号时不会回退到同号新账号。直接邀请贡献保留绑定及交易的微秒顺序，同一毫秒内早于绑定的行为不计入。
