# 行为路径性能优化 · 2026-10-24

## 结论

本轮针对行为路径页优化，保留已有取数/内存/结果预算，不通过缩小统计窗口或丢弃会话提高速度。主路径先显示，页面访问、首屏停留、请求与价值诊断展开时再读取。

同一快照的本地样本对比：

| 测量 | 原完整预加载 | 主路径优先 |
| --- | ---: | ---: |
| 后端任务均值（各2次） | 5072ms | 2376ms |
| 首批事件数 | 118832 | 58904 |
| 首批公开payload | 1180946字节 | 194250字节 |
| 浏览器点击到路径可见（各1次） | 7850ms | 3399ms |
| 初始路径DOM元素 | 4724 | 318 |

浏览器两模式同快照、同统计期，均1422会话；后端基准采样更早，同一固定快照两模式均1421会话。采样时段不同，不应将两个会话数混为同一次测试。浏览器为实际localhost:5173登录页面，先等已有导航请求空闲；两模式均加验证用作业标识避免复用已完成作业。DB及网络缓存不受控，样本量小，不作为冷启动或P95承诺。另一次正常导航实测主路径约4.8秒，包含并发任务与轮询等待。

## 实现

- 前端主路径请求details=false，保留路径图、会话结束状态、路径排行、页面/设备节点诊断及准确用户名单。
- graphOnly事实加载只读业务路径事件及图表必要的页面、设备、视口字段，保持完整相关显式会话和推断会话边界。SQL顺序仍按时间/event_id，轻量传输不携带图表不使用的event_id值。
- pathInsights在轻量模式跳过页面访问、跳出、请求级及价值诊断；details未传或true仍保持完整接口行为，兼容既有调用方。
- “页面访问、停留与请求诊断（按需加载）”展开后请求/api/metrics/path-details。服务端从原作业取得日期、来源、路径选项、已解析的固定人群与快照；忽略客户端覆盖，不重新解析可能已修改的人群配置。
- 诊断和图表作业按既有owner隔离；跨账号、过期作业或过期快照明确失败，不偷偷改用最新快照。
- 展开期间合并重复请求，加载后重新展开不再请求；错误可重试，切页/换条件后迟到响应不覆盖页面。页面诊断下钻使用诊断作业自己的缓存和名单。
- 原始事件、四日核心用户定义、其他分析专题的默认口径没有改变；未接入新缓存基础设施或修改源数据库。

## 验证

1. 固定快照，对比优化前完整结果和轻量结果：会话数、人数、推断会话、平均步数、结束状态、路径、图、节点页面/设备诊断及轻量保留的全部名单一致。
2. 按需加载后的页面、跳出、请求及价值诊断与原完整结果一致。
3. 接口回归覆盖原作业owner、来源、路径参数、空名单、参数抗覆盖及过期快照；前端覆盖展开才发请求、一次加载、多次展开、快照不一致、错误重试及迟到响应隔离。
4. 本地真实浏览器确认首图、完整诊断展开和重新展开；诊断与图使用相同快照，展开仅1次网络请求，无页面脚本错误。
5. 后端335项通过；前端265项通过、4项既有跳过；构建及git diff --check通过。

证据及复现脚本位于output/path-performance-2026-10-24/：before.json、after.json、summary.json、browser-compare.json、local-page.json与桌面/手机截图。

## 边界与启用

全部诊断首次展开仍需约5—6秒，本轮改善的是主路径首屏，不宣称完整诊断免费。数据量进一步增长或大量缺失/复用session_id时，仍可能触及明确预算。下一步优化应继续以实际慢查询、作业等待和用户使用频率为依据。

本地watch与Vite已加载变更，并在用户实际运行页面验证。没有部署到外部环境；其他环境需更新前端构建并正常重启后台。
