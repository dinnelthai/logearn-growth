# 性能复查与优化 · 2026-10-17

## 已有优化

上一轮已实现邀请注册的会话事件索引、页面动态加载、图表库延后加载、JSON 资源隔离及缓存容量控制。详情见 [update](../UPDATE_2026-10-17.md)。缓存上限控制资源增长，不等同于每次请求都提速。

## 本轮已实施

### 运营对比与 KOL 多人群统计

原来 `compareFacts` 对每个活动/KOL 都调用 `memberMetrics` 扫描同一份全部事件、交易。KOL 列表还会分别计算本人、邀请用户、标签用户及排除本人标签用户，多次重复扫描。

新增 `memberFactIndex.js`，一次按用户建立事件和交易位置索引，每组只聚合自身成员的事实。已接入 `operationsComparison.js` 及 `data/kolMetrics.js`。保留输入原始顺序，避免重复事件、冲突交易的去重结果或浮点金额累计顺序改变；仍由原聚合器处理邀请绑定微秒边界、统计期和来源缺失。并集继续保留各组观察窗口，活动间的时间空隙不纳入贡献。

### 邀请报表分组与回访

原来每遇到一个来源、邀请人、链接、活动或失败原因，就重新过滤全部流程；不同链接和活动越多，越接近平方级工作量。

改为一次分组后聚合，各分组保留首次出现顺序、稳定的下钻 key 和原名单顺序。回访阶段通过用户 ID 索引替代每个被邀请人的全用户数组查找。邀请关系验证、注册判断和统计口径沿用既有实现。

索引增加与事实条数成正比的内存。多人群重叠非常高或只有一个很小分组时，收益可能较低，本轮不声称降低峰值内存。

## 80/20 收敛执行 · 用户要求只做主要收益

本轮只保留一项查询范围优化：**登录转化不再搬运无关页面、筹码分析和邀请历史**。不扩展到并发、worker 池、图表类型拆分或数据库结构改造。

### 保留：缩减登录事件上下文

- `data/conversionFacts.js` 增加明确的登录查询模式；`workers/remoteAnalysis.js` 仅对登录转化启用。邀请查询保持全量上下文和既有入口去重规则。
- 候选用户范围保持不变。返回全部登录按钮、登录成功、登录尝试及阶段事件，另保留每位用户真实最早的非登录观测；不伪造历史标记。
- 保留该观测是为了维持“此前已观测 / 本期首次观测”的分类，以及只有页面行为、没有登录行为的候选成员。按登录方式过滤后也保留这些事实。
- 只对登录场景在数据库投影完整属性前收窄返回行数，降低传输、JSON 处理、worker 内存及后续计算输入量。没有简单截断历史登录或跨期尝试。

真实 Hologres 只读验证：同一快照、最近 1 小时统计窗口，21 位候选用户；每版三次运行中位数。完整输出在全部方式、wallet、google 筛选下深比较一致。

### 未采用：交易查询先选键再聚合

测试过先选目标账号的交易键，再对键对应的全部记录做冲突检查，以保持原交易口径。真实库最近 28 天、10 个目标账号、2,385 行结果完全一致，但三次运行中位数仅从 452.42ms 变为 430.00ms，约 5% 差异，收益不足以支持增加查询复杂度；已撤回，`memberMetrics.js` 保持本轮前实现。
